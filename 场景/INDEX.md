## 一、路由协议

**第 0 步 · 拆条**：复合需求先按功能点拆分（一个句群一个功能点），每个功能点独立走下面的路由；复合样本逐子句判定（回测口径）。

**第 1 步 · 主路径——场景路由**：拿功能点的关键词（名词与动词）对照 §三 场景信号表，命中信号词即路由到该场景的规则。一个功能点可命中多个场景（如"导入失败提示"→ S03 + S19），每个场景的规则都要查。

**第 2 步 · 副路径——词类路由**：场景定位不了，或句子呈现典型词类形态（主观形容词 / 愿望陈述 / 开放谱系动词 / 欠约束公式）时，走 §五 词类路由直接定位规则族。

**第 3 步 · 必查规则**：无论路由结果如何，§二 的必查规则对整篇文档执行一遍——它们检的是跨场景结构缺陷。

**第 4 步 · 兜底**：两条路径都定不了位的句子 → 报"场景外文本，留人工判断"，不硬套规则。规则命中与否**只以规则文件内的 F/B 特征与判定式为准**，本文件的信号词只是路由召回，不构成判定依据。

> 判定纪律（继承自规则库约定）：反向特征（B）是灭火器——出现任何一个，无论正向特征多完整都不命中；误报注意 / 漏报注意段落优先级高于字面词匹配。

## 七、路由维护

1. **四处同步**：规则新增或增强时，同步 ① 规则文件 frontmatter ② 本文件 §三/§四/§五 ③ [覆盖矩阵](../覆盖矩阵.md) ④ 测评集验证档案——缺一即索引失真；
2. **信号词先于规则**：信号词表是路由召回词表，新场景入库但规则未沉淀时，场景行照挂（规则列标"待沉淀"），不要等；
3. **场景 ID 冻结**：43 场景 ID 永不变更，新场景尾部追加并同步本表；
4. **必查规则严进**：§二 只收录"任何需求都可能命中"的元规则，普通规则不升级；
5. **职责分离**：本文件只回答"去哪"（路由），规则文件只回答"是否命中"（判定）——路由不复制 F/B 细节，判定不依赖本文件存在。
