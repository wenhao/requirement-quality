# R-S15-P1 状态机只列状态名未定义流转规则

- **场景**：S15 状态机　**标签**：[P1-不完整](../../知识库/无效需求标签.md)
- **验证**：多解实现验证通过（2026-10-20，N=3，5 组冲突性假设：已支付取消/取消来源集合/系统自动流转/终态可操作性/非法流转处置）

## 命中条件

**正向特征（须出现）**：

- **F1 状态集合声明**："有 / 包括 / 分为 + 状态名词列举"（顿号、逗号连接的名词并列清单），或"状态包括 + 枚举表"类结构。
  - 例："订单**有**待支付、已支付、已发货、已完成、已取消**这几个状态**" → F1 成立。
- **F2 初始状态或单一流转描述**：出现初始状态或一条流转（"下单后进入 xx 状态"、"xx 后变为 yy"），描述止于**状态清单层面**，无流转规则体系。
  - 例："**用户下单后订单进入待支付状态**" → F2 成立。

F1 与 F2 同时出现。

**反向特征（须全部不出现）**——出现任何一个即不命中：

- **B1 流转规则**：状态对状态的条件式定义——"xx 状态**才能 / 方可 / 允许**变更为 yy"、"仅 xx 状态可取消/退款/发货"。
  - 例："**仅待支付状态可取消**，已支付订单不可取消" → B1 出现。
- **B2 变更主体**：谁（用户 / 运营 / 系统 / 商家）能执行哪个状态变更的说明。
  - 例："**运营**可以取消已支付订单，**用户**只能取消待支付订单" → B2 出现。
- **B3 非法流转处置**：非法/并发流转的拦截或防护说明。
  - 例："**非法状态变更直接拒绝**并告警" → B3 出现。

### 判定

```
(F1 ∧ F2) ∧ ¬B1 ∧ ¬B2 ∧ ¬B3 → 命中 R-S15-P1
```

判定式读法：**左边**（列了状态集合、给了初始状态或单条流转）**同时右边**（流转规则、变更主体、非法流转处置一个没提）→ 命中。

### 判定过程示例

**例 1（命中）**：

> "订单有待支付、已支付、已发货、已完成、已取消这几个状态，用户下单后订单进入待支付状态。"

| 特征 | 结果 | 依据 |
|---|---|---|
| F1 | ✓ | "有待支付、已支付…这几个状态" |
| F2 | ✓ | "下单后进入待支付状态" |
| B1 | ✗ | 无任何"仅 xx 状态可 xx"规则 |
| B2 | ✗ | 谁能变更状态全无 |
| B3 | ✗ | 非法流转处置无 |

→ **命中**：实证显示 5 组互斥实现——已支付订单能否取消（无入口走售后 vs 仅运营可取消 vs 用户一键取消+退款）、取消来源集合（仅待支付 vs 含已支付 vs 含已发货可配置）、系统自动流转（强制超时关单 vs 可配置 vs 完全不做）、终态可操作性（自助售后起点 vs 运营强制取消 vs 彻底终态）、非法流转（强拦截 vs 配置拦截 vs 不拦截出现脏状态）。

**例 2（不命中）**：

> "订单状态包括待支付、已支付、已发货、已完成、已取消；仅待支付状态可由用户取消，已支付订单由运营在发货前取消，未定义的状态变更一律拒绝。"

B1（"仅待支付状态可由用户取消"）、B2（用户/运营分工）、B3（"未定义的变更一律拒绝"）出现 → **不命中**。

## 说明

本规则检测状态类需求的**流转体系缺失**，与状态集合的具体内容无关（订单/工单/合同/项目状态机均适用）。缺口实质：状态机需求 = 状态集合 + 初始状态 + **流转规则（条件×主体×方向）+ 异常处置**。只列状态名是把"状态机"降格为"枚举字段"——状态名本身有业务常识约束（没人会让已完成的订单直接变回待支付），真正的纯决策空间在流转规则：谁能改、从哪到哪、改不了怎么办。这些规则不同实现给出互斥答案，且每一组都直接决定用户在关键操作点（取消、退款、售后）看到什么界面、能做什么。

## 误报注意

1. **状态机图引用**："状态流转见流程图/状态机图"——B1/B2 以外部形式存在，需人工确认图覆盖度（含并发与回退边）；
2. **无流转语义的纯标记集合**：若上下文表明状态仅作展示标签（如订单列表的筛选维度）而非生命周期，流转规则缺失影响面不同，降级为提示；
3. **状态由外部系统托管**："订单状态以 ERP 为准，本系统只读"——流转规则在外部系统，本系统无需定义，不命中。

## 漏报注意

1. **部分流转规则**：写了"待支付可取消"但已支付/已发货后怎么办没说——B1 出现打破命中，但其余状态的流转仍开放，属"部分定义"变体，需语义级判定（逐状态核对每个非终态的出边是否都有归属）；
2. **规则藏在状态命名里**："待支付、已支付、已取消（用户）"用括号标注主体——B2 以弱形式存在，扫描需识别括注、脚注等非正文规则载体；
3. **口语化流转**："货没发都能退"——流转规则以口语表达，B1 词表需覆盖"能/不能/才"类口语条件结构。
