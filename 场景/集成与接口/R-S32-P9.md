# R-S32-P9 多端支持未界定程度与端间关系

- **场景**：S32 多端适配　**标签**：[P9-范围失焦](../../知识库/无效需求标签.md)
- **验证**：多解实现验证通过（2026-10-20，N=3，6 组冲突性假设：功能覆盖/支付渠道/登录身份/发布节奏/端间裁决/页面形态）

## 命中条件

**正向特征（须出现）**：

- **F1 多端支持声明**："支持/需要支持/做 + 端名并列（App / 小程序 / Web / H5 / PC…，两端及以上）"类结构。
  - 例："**需要支持 App 和小程序双端**" → F1 成立；"要覆盖 Web 和移动端" → F1 成立。
- **F2 支持程度裸奔**："支持"到什么程度（功能对齐还是差异分工）、账号与数据是否互通、端间不一致以谁为准**全部未界定**。

**反向特征（须全部不出现）**——出现任何一个即不命中：

- **B1 功能范围界定**：各端功能覆盖的说明（全对齐 / 某端裁剪哪些功能）。
  - 例："小程序**只做浏览和基础下单**，会员功能仅 App" → B1 出现。
- **B2 互通关系界定**：账号/数据跨端互通的说明。
  - 例："双端**同一账号，数据实时同步**" → B2 出现。
- **B3 端间裁决口径**：双端行为不一致时的优先级或客服口径。
  - 例："功能与数据**一律以 App 为准**，小程序做引导下载" → B3 出现。

### 判定

```
(F1 ∧ F2) ∧ ¬B1 ∧ ¬B2 ∧ ¬B3 → 命中 R-S32-P9
```

判定式读法：**左边**（声明支持双端，但"支持"到什么程度没说）**同时右边**（功能范围、互通关系、裁决口径一个没出现）→ 命中。

### 判定过程示例

**例 1（命中）**：

> "需要支持 App 和小程序双端。"

| 特征 | 结果 | 依据 |
|---|---|---|
| F1 | ✓ | "支持 App 和小程序双端" |
| F2 | ✓ | 支持程度全裸奔 |
| B1 | ✗ | 功能对齐/分工无 |
| B2 | ✗ | 账号互通无 |
| B3 | ✗ | 裁决口径无 |

→ **命中**：实证显示 6 组互斥——功能覆盖（双端全对齐 vs 小程序裁掉会员/深度功能 vs 同一套 H5 全量——小程序用户能否用全部功能三案不同）、支付渠道（双端仅微信支付 vs App 多通道+小程序仅微信 vs 小程序内支付受限需跳转降级——App 用户能否用支付宝、小程序能否一路付完）、登录身份（双端微信授权同一身份 vs 小程序微信+App 手机验证码 vs 双端手机验证码——换端使用是否被迫换登录方式、能否识别为同一人）、发布节奏（同版本号同步发版 vs 小程序周更 App 月更 vs H5 热更即时——同一新功能双端上线时间差可达数周）、端间裁决（端间平行不引导 vs 以 App 为准+主动引导下载+客服同口径 vs 无端间概念——小程序用户是否被持续引导跳转 App、投诉归责口径不同）、页面形态（端级原生渲染 vs webview 网页级加载——小程序页面是否白屏转圈、弱网可用性）。

**例 2（不命中）**：

> "支持 App 和小程序双端：功能全量对齐；同一账号 unionid 打通，数据实时同步；微信生态限制导致的行为差异以 App 为准并提示用户。"

B1、B2、B3 全部出现 → **不命中**。

## 说明

本规则检测多端适配类需求的**支持程度失焦**，与端组合无关（App/小程序/Web/PC 双端或多端均适用）。缺口实质：多端需求 = 功能范围 × 互通关系 × 端间裁决。"支持双端"中"支持"是程度动词——从"同一套页面跑在两端"到"两端各自定位分工"再到"一端为主一端为辅"，光谱上每一点都是合理产品，而不同选择产出完全不同的系统：全对齐派用一套核心，分工派两套团队，H5 壳派一套页面。裁决口径（以谁为准）看似细节，实为运营与客服的日常依据——功能不对齐的端，用户投诉"小程序里没有 xx"时客服答什么，取决于这个从未写下的决定。P9 的判定证据在实证中很纯：六组冲突全部由"支持"一词的开放解释直接派生，没有一组来自实现自由度。

## 误报注意

1. **响应式 Web 需求**："官网要适配手机浏览器"——响应式适配无功能/账号/裁决维度（同一系统不同屏幕），不命中本规则（走 S34 兼容环境）；
2. **端定位已在前文**：上下文已写明"小程序做拉新、App 做留存"的分工战略——B1 以战略形式存在，跨段落核对后不命中；
3. **明确的最小支持**："双端只是都能打开、功能看各自进度"是显式分期决策——范围已圈定（暂不对齐），不命中（但应确认验收方知情）。

## 漏报注意

1. **互通半界定**："账号互通"出现 B2 但功能对齐/裁决仍开放——部分定义变体，逐要素核对；
2. **"双端一致"迷惑词**："双端体验保持一致"——是一致对齐还是一致地都不做某功能？词面无解，需按 B1 实质判定；
3. **隐含单端主体**：上下文全文以 App 为主体叙述、小程序仅一句带过——单边视角下小程序的范围（B1）系统性缺失，需显式核对次要端的每个要素。
