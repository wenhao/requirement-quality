# 调研方法论

> 本文档记录"需求有效性"调研的整体思路与核心决策（2026-10-19 grill-me 审查会话定稿），是仓库一切产出的方法论依据。

## 背景

研究目标：什么样的需求描述拿去开发，会产出一个"能用但不符合预期"的结果。

冷启动难题：手头没有真实需求样本，无法从真实缺陷出发归纳。因此采用**先合成穷举、后真实校准**的路线。

## 核心思路

**穷举需求分析的场景，再通过 AI 在每个场景下穷举无效需求的写法。** 因为没有实际的需求，只能先穷举场景再去验证。

整个调研围绕一个中心产出物展开，由三层机制支撑。

## 五项核心决策

### 1. 终极产出物：场景 × 缺陷矩阵清单

- 矩阵以场景为行、缺陷类型为列；
- 空格 = 未覆盖的盲区，直观暴露穷举遗漏；
- 可降级为 AI 辅助需求澄清（clarifier）的规则 / prompt 素材。

### 2. 矩阵主轴：场景

场景做主轴（而非缺陷类型），保留原始思路。配套代价是必须解决场景穷尽性问题：

- **穷举依据**：外部分类学交叉对照——用 ISO/IEC/IEEE 29148 需求分类、主流 PRD 模板章节结构、需求缺陷（requirement smells）学术分类等外部权威来源交叉拼出场景骨架；
- **穷尽判据**：多来源交叉后无新增场景，即视为穷尽；
- 避免凭直觉往下列场景——列漏一个场景，矩阵就有一整行盲区。

### 3. AI 生成样本的质检：多解实现验证法

AI 生成"无效需求写法"很容易，但可能出现伪缺陷（信息其实够了，是 AI 过度挑刺）或同质化（变着措辞重复同一缺口）。判定机制：

- 把候选需求描述交给 **N 个相互独立的 AI 开发者**各自实现；
- **产出分歧显著 = 信息缺口实证存在**（必填规则不同、边界处理不同等）；
- 产出趋同 = 伪缺陷，剔除；
- 分歧点直接写入样本的"缺陷分析"段，作为缺陷的实证证据；
- 全流程可自动化，辅以少量人工抽检校准。

### 4. 合成与真实样本：双层闭环互哺

- **合成层**：AI 穷举 + 多解验证，先铺满矩阵骨架（解决冷启动）；
- **真实层**：从开源项目 issue / 公开 SRS/PRD 文档 / 外包平台公开需求描述主动采集；
- **回测机制**：真实样本进来后检验能否被矩阵已有模式解释——能 → 覆盖度 +1；不能 → 盲区，新增行列；
- 两条线从并列变为互哺：合成层提供结构，真实层校准分布。

### 5. 物理承载：场景/ 规则库 + 覆盖矩阵.md

`场景/` = **规则库本身**（skill / clarifier 的唯一消费源），不再保留案例层：

- 场景目录 = 矩阵的行（`场景/数据录入/` 对应 S01–S04…）；
- 规则文件 = 矩阵的格子：文件名 = 规则 ID = `R-<场景>-<标签>`（如 `场景/数据录入/R-S01-P1.md`），一格一文件，天然防重复；
- 规则内容无关、自包含：命中条件（正向 F / 反向 B + 布尔判定）→ 说明 → 误报注意 → 漏报注意 → 追问方向（clarifier 命中后要求补充的通用清单）；多解验证结论压缩为头部一行元数据；
- 顶层 `覆盖矩阵.md` 汇总行 × 列覆盖视图，从规则文件存在性自动汇总，空格即盲区；
- 覆盖标准：每个矩阵格子一条**通过多解验证的规则**才算"已覆盖"。

**为何不保留案例**：仓库的消费方式是"拿规则去扫描其他需求"，具体案例（"做一个用户信息登记表单…"）既不参与判定又占上下文，对 skill 是噪声。案例的唯一价值（人读理解、规则回归测试）由规则的"说明 + 误报/漏报注意"段落承担——规则写到自解释，就不需要例子。合成候选与验证记录仍留在 知识库/候选池.md 作过程档案，不进入规则。

**沉淀的裁决规则**：

- 规则与格子一一对应：同格已有规则 → 修订（特征取并集、验证结论合并），不开新文件；
- 候选验证通过后，先查同格是否已有规则，有则增强，没有才新建。

## 执行顺序

```
外部分类学拼场景骨架
        │
        ▼
AI 逐场景生成无效写法候选 ──► 多解实现验证 ──► 同格查重（已有规则则增强）
        │                                         │
        └────────── 可并行流水线化 ────────────────┘
                                                  │
                                                  ▼
                              沉淀规则（场景/<场景>/R-<场景>-<标签>.md，
                              含误报/漏报注意与追问方向）
                                                  │
                                                  ▼
                                    更新 覆盖矩阵.md
                                                  │
                                                  ▼
                                    真实样本回测矩阵覆盖度
```

其中"生成 → 验证 → 查重 → 沉淀"四步可流水线化批量推进。产出物消费路径：**skill / clarifier 只加载 `场景/` 下的规则文件**（按场景目录组织，文件名即格子坐标）。

## 与真实需求样本的关系

"收集真实写法样本"的原始定位演化为**回测机制**：真实需求（开源 issue / 公开 SRS / 外包平台）不作为仓库内容入库，而是拿去**回测规则库**——能被现有规则命中 → 覆盖度 +1；命不中 → 盲区，驱动新增或修订规则。合成层提供结构（规则），真实层校准分布（回测），两层互哺但物理上分离：仓库里只有规则，真实需求留在回测报告里。
