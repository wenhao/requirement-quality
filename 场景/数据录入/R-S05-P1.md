# R-S05-P1 批量删除未定义语义边界与恢复

- **场景**：S05 删除与批量操作　**标签**：[P1-不完整](../../知识库/缺陷标签.md)
- **验证**：多解实现验证通过（2026-10-20，N=3，5 组冲突性假设：删除语义/失败策略/确认强度/权限/数据去向）

## 命中条件

**正向特征（须出现）**：

- **F1 删除操作声明**："支持 / 需要 / 可以 + 批量删除 / 批量移除 / 一次删除多个 + 实体名"类结构。
  - 例："**支持批量删除**订单" → F1 成立。
- **F2 极简表述**：需求仅为操作声明（一句话以内），批量上限、失败处理、确认方式、删除后数据去向**全部缺席**。
  - 例："支持批量删除订单。"（全文止于此）→ F2 成立。

F1 与 F2 须同时出现。

**反向特征（须全部不出现）**：

- **B1 删除语义定义**：物理删除 / 软删除 / 回收站 / 恢复期 任一说明。
  - 例："删除后进入**回收站，保留 30 天**可恢复" → B1 出现。
- **B2 失败策略**：部分失败的处理定义（逐条反馈 / 整批回滚）。
  - 例："部分失败时**已成功的照常删除**，失败行**逐条标注原因**" → B2 出现。
- **B3 确认与保护**：二次确认 / 强确认（输入文字）/ 批量上限 任一保护机制。
  - 例："需**输入'删除'确认**，单次上限 **100 条**" → B3 出现。

### 判定

```
(F1 ∧ F2) ∧ ¬B1 ∧ ¬B2 ∧ ¬B3 → 命中 R-S05-P1
```

判定式读法：**左边**（要批量删除，就一句话）**同时右边**（删除语义、失败策略、确认保护全没定义）→ 命中。

### 判定过程示例

**例 1（命中）**：

> "支持批量删除订单。"

| 特征 | 结果 | 依据 |
|---|---|---|
| F1 | ✓ | "支持批量删除订单" |
| F2 | ✓ | 全文一句，四要素全缺席 |
| B1/B2/B3 | ✗ | 语义/失败/确认全无 |

→ **命中**：实证显示删除语义三案互斥——软删+回收站 30 天自助恢复、物理删除直接消失、软删 90 天仅内部可追溯；"删 10 条失败 1 条"后三种实现分别给出剩 9 条、剩 10 条（回滚）、不知道几条（模糊 toast）三种结果。

**例 2（不命中）**：

> "支持批量删除订单：软删除进回收站保留 30 天，单次上限 100 条需二次确认，部分失败时逐条反馈原因。"

B1（软删+回收站）、B2（逐条反馈）、B3（上限+确认）出现 → **不命中**。

## 说明

本规则检测批量删除需求的**风险要素缺失**，与实体领域无关（订单/会员/商品/日志删除均适用）。缺口实质：删除需求 = 删除语义（物理/软删/恢复路径）× 失败策略 × 确认与保护 × 权限边界 × 数据去向。删除是唯一"做错了无法退回"的常规操作——语义分歧直接决定"删错后能否找回"这一最高风险后果：物理删除下误删即永久丢失，软删除下可自助恢复。批量放大了风险：单条误删尚可手工补救，批量误删是事故级。P9（五个字全开放）在此并入说明：删除类需求越短，开放的风险决策空间越大。单条删除与批量删除共享此缺口结构（确认保护除外），本规则对"支持删除 xx"的单条表述同样适用。

## 误报注意

1. **平台删除惯例**："删除逻辑与系统其他列表一致（软删+回收站）"——B1 以平台惯例形式存在，需人工确认惯例真实覆盖；
2. **明确的一次性清理**："把测试数据全清了，物理删除"——一次性运维任务带明确语义，不命中；
3. **低风险数据**：草稿/缓存类数据删除，恢复需求弱——降级为提示而非缺陷。

## 漏报注意

1. **有确认无语义**："删除需二次确认"——B3 出现打破命中，但物理/软删语义未说仍是最高风险缺口（确认保护不了"删错类型"）；
2. **伪语义**："支持安全删除""可恢复地删除"——"安全/可恢复"无恢复路径与保留期定义，应仍命中；
3. **口语化删除**："能一次勾选一堆删掉""清掉这些"——F1 词表需覆盖口语批量删除表述。
