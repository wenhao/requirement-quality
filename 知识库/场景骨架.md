# 场景骨架 v1

> 本文档是**需求分析场景的分类骨架**，是"场景 × 缺陷矩阵"的行来源。构建方法：外部分类学交叉对照（见 [METHODOLOGY.md](../METHODOLOGY.md) 决策 2）——用多个相互独立的权威来源交叉拼合，**多来源交叉后无新增场景即为穷尽判据**。本文档即该判据的初版验证记录。

## 构建方法

场景骨架不凭直觉罗列，而是从四族独立来源交叉对照得出：

| 来源族 | 具体来源 | 主要贡献 |
|---|---|---|
| **A. 国际标准** | ISO/IEC/IEEE 29148:2018（需求工程标准：BRS/StRS/SyRS/SRS 四层、SyRS 十五个需求子条款）；ISO/IEC 25010（产品质量模型，2023 版 9 特性） | 需求的**抽象层级**与**质量维度**，防止只从 UI 形态出发 |
| **B. 质量模型** | FURPS+（HP）；SEI/Bass 质量属性（运行时/开发时二分） | 非功能场景的实用切分 |
| **C. 学术缺陷分类** | requirement smells 系统综述（Montgomery 等 15 种 smell）；Rimay 九 smell 目录 | 缺陷类型（矩阵**列**）来源，同时反向检验场景是否遗漏"易发缺陷的场景" |
| **D. PRD 实践模板** | 中文主流 PRD 模板（人人都是产品经理/ONES/英飞等常见章节结构） | 确保骨架落在真实产品工作流上，不是学术玩具 |

**交叉验证结果**：四族来源映射到统一骨架后，各来源条目均能归入已有分组，**无新增场景组**——满足 v1 穷尽判据。

## 场景骨架（8 组 32 场景）

### 1. 数据录入（data-entry）

| ID | 场景 | 典型需求表述 | 来源 |
|---|---|---|---|
| S01 | 表单（新增/编辑） | "做一个 xx 登记表单" | D：PRD 功能模块 |
| S02 | 字段级校验 | 必填/格式/长度/唯一性 | D + C：incomplete condition |
| S03 | 批量导入 | Excel/CSV 导入 | D：PRD 数据需求 |
| S04 | 富文本/文件上传 | 附件、图片、大小与类型限制 | D |

### 2. 数据消费（data-view）

| ID | 场景 | 典型需求表述 | 来源 |
|---|---|---|---|
| S05 | 列表/表格 | "做一个 xx 列表页" | D |
| S06 | 搜索/筛选 | 关键词搜索、组合筛选 | D |
| S07 | 详情页 | 查看单条记录全貌 | D |
| S08 | 排序/分页 | 默认排序、每页条数 | D |
| S09 | 报表/统计 | 汇总报表、可视化图表 | D：PRD 数据需求 |
| S10 | 导出 | 导出 Excel/PDF | D |

### 2 的补充说明

数据录入与数据消费共同构成"数据闭环"（录入→存储→消费），v1 阶段作为一个层次并列。

### 3. 流程与状态（flow-state）

| ID | 场景 | 典型需求表述 | 来源 |
|---|---|---|---|
| S11 | 业务流程/审批流 | "做一个 xx 审批流程" | D：PRD 业务流程图 |
| S12 | 状态机 | 状态流转、谁能变更状态 | C：correctness/order |
| S13 | 异常/回退/撤销 | 失败、超时、撤回 | C + README 已有"流程断点" |
| S14 | 定时/触发任务 | 定时跑批、事件触发 | A：SyRS 系统模式与状态 |

### 4. 交互反馈（interaction）

| ID | 场景 | 典型需求表述 | 来源 |
|---|---|---|---|
| S15 | 提示/通知 | 站内信、Toast、短信邮件 | D |
| S16 | 确认/二次确认 | 危险操作确认弹窗 | D |
| S17 | 加载/进度 | Loading、进度条、骨架屏 | D |
| S18 | 空态/首次使用 | 无数据时的展示 | README 已有"缺少边界条件" |

### 5. 权限与安全（auth-security）

| ID | 场景 | 典型需求表述 | 来源 |
|---|---|---|---|
| S19 | 角色与权限 | "支持权限管理" | D + A |
| S20 | 登录/认证 | 账密、SSO、验证码 | D |
| S21 | 数据权限/隔离 | 谁能看到哪些数据 | D：PRD 业务规则 |
| S22 | 审计/日志 | 操作留痕 | A：information management |

### 6. 集成与接口（integration）

| ID | 场景 | 典型需求表述 | 来源 |
|---|---|---|---|
| S23 | 第三方 API 集成 | 对接微信/支付/CRM | D：PRD 第三方集成 |
| S24 | 数据同步/接口约定 | 字段映射、频率、失败重试 | A：interface requirements |
| S25 | 消息推送/回调 | Webhook、MQ | A |
| S26 | 多端适配 | Web/App/小程序行为差异 | D：兼容性 |

### 7. 非功能（non-functional）

| ID | 场景 | 典型需求表述 | 来源 |
|---|---|---|---|
| S27 | 性能与容量 | "响应要快"、并发数 | B：FURPS Performance / 25010 性能效率 |
| S28 | 兼容性与环境 | 浏览器/OS/分辨率 | B：25010 兼容性/可移植 |
| S29 | 可用性/易用性 | "界面要美观易用" | B：25010 易用性 |
| S30 | 可靠性与恢复 | 可用性 %、故障恢复 | B：25010 可靠性 |

### 8. 需求管理本身（meta）

| ID | 场景 | 典型需求表述 | 来源 |
|---|---|---|---|
| S31 | 范围/优先级 | 本期做什么不做什么 | D：PRD 需求范围；A：BRS |
| S32 | 验收/成功标准 | "做到什么程度算完成" | D：验收标准；ISO 29148 verifiable |

> **命名约定**：`cases/` 目录名与场景组对应（`cases/form/` 对应 S01–S04 等），样本不再自创新场景组——发现骨架未覆盖的场景时，先修订本骨架再新增目录。
