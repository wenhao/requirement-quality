# R-S03-P1 批量导入未定义模板重复与失败边界

- **场景**：S03 批量导入　**标签**：[P1-不完整](../../知识库/无效需求标签.md)
- **验证**：多解实现验证通过（2026-10-20，N=3，8 组冲突性假设：模板/重复/失败边界/校验强度/规模/反馈/状态/审计）

## 命中条件

**正向特征（须出现）**：

- **F1 导入功能声明**："做一个/需要/支持 + 批量导入 / 导入 / Excel 导入 / 一次导入一批"类结构。
  - 例："**做一个**会员**批量导入功能**" → F1 成立。
- **F2 导入主体为角色+格式级表述**：只说谁导入（运营/管理员）、导什么格式（Excel/CSV），**未定义模板列与数据规则**。
  - 例："**运营**可以上传 **Excel** 一次导入一批**会员**" → F2 成立（模板列有哪些？未说）。

F1 与 F2 须同时出现。

**反向特征（须全部不出现）**：

- **B1 模板定义**：模板下载/列定义/表头说明，或"按 xx 模板填写"。
  - 例："提供**模板下载**，列含手机号/姓名/等级" → B1 出现。
- **B2 重复策略**：重复数据处理定义（跳过/覆盖/报错/整批拒绝）。
  - 例："与已有会员重复时**跳过并记录**" → B2 出现。
- **B3 失败边界**：部分失败的处理定义（全回滚 / 跳过继续 / 校验不过整批拒）+ 结果反馈方式。
  - 例："任一行校验失败**整批拒绝**并返回**错误明细**" → B3 出现。

### 判定

```
(F1 ∧ F2) ∧ ¬B1 ∧ ¬B2 ∧ ¬B3 → 命中 R-S03-P1
```

判定式读法：**左边**（要做批量导入，只说了角色与格式）**同时右边**（模板、重复策略、失败边界全没定义）→ 命中。

### 判定过程示例

**例 1（命中）**：

> "做一个会员批量导入功能，运营可以上传 Excel 一次导入一批会员。"

| 特征 | 结果 | 依据 |
|---|---|---|
| F1 | ✓ | "做一个…批量导入功能" |
| F2 | ✓ | 运营 + Excel + 会员，模板列未说 |
| B1/B2/B3 | ✗ | 模板/重复/失败全无 |

→ **命中**：实证显示 8 组冲突性假设——同一份含 1 行错误的 100 行文件，三种实现分别给出"0 行入库（整批拒）""99 行入库（跳过继续）""0 行入库（全回滚）"三种结果；导 2 万行时分别"转异步有进度""页面转圈至超时""返回任务号后台跑"。

**例 2（不命中）**：

> "会员批量导入：提供模板下载（手机号/姓名/等级三列），与存量重复的行跳过并在结果中标注，任一行校验失败整批拒绝并返回错误明细文件。"

B1（模板三列）、B2（重复跳过+标注）、B3（整批拒+明细）出现 → **不命中**。

## 说明

本规则检测批量导入需求的**数据边界要素缺失**，与导入领域无关（会员/商品/订单/考勤导入均适用）。缺口实质：批量导入需求 = 模板契约 × 重复策略 × 失败边界（事务语义）× 校验强度 × 规模与交付方式 × 结果反馈。其中失败边界是隐形雷区：逐行插入（部分成功）与整批事务（全有或全无）对用户是两种完全不同的功能——前者留下"半干净"数据，后者要求用户改完全部错误才能导入。本场景在数据消费组对应物是导出（R-S12-P1），一对孪生场景共享"范围 × 边界 × 量级"的缺口结构。8 组冲突假设为全库目前最高，说明"一句话导入需求"的开放决策空间最大。

## 误报注意

1. **模板外部引用**："模板见运营手册/由数据组提供"——B1 以外部形式存在，需人工确认模板真实存在且列定义完整；
2. **小规模确定性**：上下文明确单次导入恒定小量（如"每月导入考勤 30 行"）——规模与异步分歧不存在，降级为提示；
3. **主体不是导入**："导入功能加个进度条"——导入已定义，主体是进度展示，不命中。

## 漏报注意

1. **有模板无策略**：给了模板下载但重复/失败策略全无——B1 出现打破命中，B2/B3 缺失仍是最常见的组合缺口，需逐要素核对；
2. **伪策略**："支持错误处理""智能去重"——"错误处理/智能"不构成具体策略定义，应仍命中；
3. **隐式模板引用**："按上次那个表头传"——口语化模板指代，F2 判定需结合上下文识别。
