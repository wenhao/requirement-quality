# R-S06-P1 引用数据删除未定义级联行为

- **场景**：S06 引用与级联约束　**标签**：[P1-不完整](../../知识库/无效需求标签.md)
- **验证**：多解实现验证通过（2026-10-20，N=3，5 组冲突性假设：级联行为/层级深度/功能范围/删除语义/同名约束）

## 命中条件

**正向特征（须出现）**：

- **F1 主数据管理声明**："做一个/需要 + xx 管理（功能/模块）"类结构，管理对象是**可被其他数据引用的主数据**（分类/标签/部门/字典/仓库/科目）。
  - 例："**做一个**商品**分类管理功能**" → F1 成立；"**需要**部门**管理**" → F1 成立。
- **F2 操作集含删除**：声明可添加/编辑/删除，其中**删除在列**，但未提被引用时的行为。
  - 例："运营可以添加**和删除**商品分类" → F2 成立。
- **F3 引用关系未提及**：全文无"引用/被使用/关联/挂靠/占用"类引用关系表述。
  - 例：通篇未提分类下有商品怎么办 → F3 成立。

F1 与 F2 须同时出现；F3 强化判定（主数据必然被引用，不提即缺口）。

**反向特征（须全部不出现）**：

- **B1 级联行为定义**：被引用时的删除行为说明（禁止删 / 级联删 / 级联下架 / 解绑置空 / 提示转移）。
  - 例："分类下**有商品时禁止删除**，提示先转移" → B1 出现。
- **B2 引用计数展示**：管理界面展示被引用数量/影响面。
  - 例："删除前**展示该分类下商品数**" → B2 出现。

### 判定

```
(F1 ∧ F2) ∧ ¬B1 ∧ ¬B2 → 命中 R-S06-P1
```

判定式读法：**左边**（要管理可被引用的主数据，操作含删除）**同时右边**（被引用时的级联行为、影响面展示全没定义）→ 命中。

### 判定过程示例

**例 1（命中）**：

> "做一个商品分类管理功能，运营可以添加和删除商品分类。"

| 特征 | 结果 | 依据 |
|---|---|---|
| F1 | ✓ | "做一个…分类管理功能"（分类可被商品引用） |
| F2 | ✓ | "添加和删除"，级联未提 |
| F3 | ✓ | 无引用关系表述 |
| B1/B2 | ✗ | 级联/影响面全无 |

→ **命中**：实证显示级联行为三方完全互斥——级联下架关联商品（前台消失）、引用拦截禁止删除（须先转移 N 个商品）、解绑置空外键 SET NULL（商品变"未分类"）；"商品挂在被删分类下会怎样"三案用户感知截然不同。

**例 2（不命中）**：

> "商品分类管理：支持增删改；分类下有商品时禁止删除并展示商品数，提示运营先转移商品至其他分类。"

B1（禁止删+转移提示）、B2（展示商品数）出现 → **不命中**。

## 说明

本规则检测主数据管理需求的**级联行为缺失**，与主数据领域无关（分类/标签/部门/仓库/科目/供应商均适用）。缺口实质：主数据删除需求的核心**就是**级联行为——禁止删（保护引用方）、级联删/下架（扩散影响）、解绑置空（数据降级为未分类）三种策略在数据安全与用户预期上互斥，且无中间答案。附带分歧同样可感知：层级深度（树/两级/扁平）与管理范围（是否含编辑排序）在"管理功能"一词下全部开放。本场景与 S05 的分工：S05 管"删除本身的语义"（物理/软删/恢复），S06 管"删除撞上引用关系时的行为"——真实需求两者常同时缺失，扫描时应两条都过。

## 误报注意

1. **无引用方的独立数据**：管理对象确无被引用可能（如独立的公告分类且公告必带分类快照）——级联问题不存在，不命中（需人工确认数据模型）；
2. **级联策略外部约定**："删除规则见数据治理规范"——B1 以外部形式存在，需人工确认规范覆盖该实体；
3. **只加不删**："分类管理：本期只支持新增和编辑，删除二期"——删除不在操作集，F2 不成立，不命中。

## 漏报注意

1. **伪级联语**："删除时注意处理关联数据"——"注意处理"不构成策略定义（禁止？解绑？下架？），应仍命中；
2. **只定义了一种引用方**：主数据被多类对象引用（商品、活动、优惠券都挂分类）但只说了商品的处理——B1 打破命中，其余引用方仍是缺口，需按引用方粒度核对；
3. **编辑撞引用**："支持重命名分类"——改名对已引用数据的影响（同步更新/快照不更新）是级联问题的编辑变体，本规则不覆盖，需语义级判定。
