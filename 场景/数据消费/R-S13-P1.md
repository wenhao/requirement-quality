# R-S13-P1 埋点需求未定义事件模型

- **场景**：S13 数据埋点与统计　**标签**：[P1-不完整](../../知识库/无效需求标签.md)
- **验证**：多解实现验证通过（2026-10-20，N=3，6 组冲突性假设：事件全集/采集通道/触发口径/用户标识/属性权威性/时效交付）

## 命中条件

**正向特征（须出现）**：

- **F1 埋点功能声明**："加上 / 做 / 需要 + 埋点 / 数据埋点 / 埋一个点 / 埋上 / 打点 / 上报"类结构。
  - 例："**给下单流程加上数据埋点**" → F1 成立。
- **F2 埋点对象为流程级指代**：对象仅到页面/流程级（下单流程 / 注册流程 / 首页），**未枚举事件**（埋哪些点、什么粒度）。
  - 例："给**下单流程**加上埋点" → F2 成立（进入算一个点？提交算一个？支付呢？未说）。
- **F3 目的语替代定义**："方便/用于/支持 + 后续分析 / 数据分析 / 分析用户行为 / 看数据"类目的表述。
  - 例："方便**后续分析用户行为**" → F3 成立（分析什么？对应埋什么？未说）。

F1 为必要条件，F2、F3 至少满足其一。

**反向特征（须全部不出现）**：

- **B1 事件枚举**：具体事件名或步骤列举（页面曝光 / 点击提交 / 支付成功…），或事件清单引用。
  - 例："埋**进入下单页、提交订单、支付成功**三个点" → B1 出现。
- **B2 触发口径定义**：事件何时触发的说明（点击即触发 / 接口成功返回 / 状态变更）。
  - 例："提交订单点以**接口返回成功**为准" → B2 出现。
- **B3 采集属性与范围**：事件属性（金额 / 渠道 / 用户标识）或采集范围（全量用户 / 仅登录用户）说明。
  - 例："携带**订单金额、渠道来源**，全量用户含游客" → B3 出现。

### 判定

```
(F1 ∧ (F2 ∨ F3)) ∧ ¬B1 ∧ ¬B2 ∧ ¬B3 → 命中 R-S13-P1
```

判定式读法：**左边**（要埋点，对象是流程级指代或用目的语替代）**同时右边**（事件、触发口径、属性范围全没定义）→ 命中。

### 判定过程示例

**例 1（命中）**：

> "给下单流程加上数据埋点，方便后续分析用户行为。"

| 特征 | 结果 | 依据 |
|---|---|---|
| F1 | ✓ | "加上数据埋点" |
| F2 | ✓ | "下单流程"流程级指代 |
| F3 | ✓ | "分析用户行为"目的语 |
| B1/B2/B3 | ✗ | 事件/触发/属性全无 |

→ **命中**：实证显示三人分别实现为 10+ 个原子 UI 微步骤事件（客户端 SDK）、5-7 个漏斗转化事件（客户端+服务端复核）、3-5 个订单状态机事件（纯服务端）——"下单成功"分别以提交响应返回、支付成功回调、落库状态转移为准，同名指标"下单转化"三家数值互斥。

**例 2（不命中）**：

> "下单流程埋点：埋进入下单页、提交订单、支付成功三个事件，提交以接口返回成功为准，携带订单金额与渠道，全量用户含未登录。"

B1（三事件）、B2（接口返回为准）、B3（金额/渠道/全量）出现 → **不命中**。

## 说明

本规则检测埋点需求的**事件模型缺失**，与埋点领域无关（下单/注册/播放/分享流程均适用）。缺口实质：埋点需求的核心内容**就是**事件模型——事件全集（粒度与清单）× 触发口径 × 采集通道 × 用户标识 × 属性集。其他场景的需求缺的是约束，埋点需求缺的是**主体本身**："给 xx 加埋点"相当于"给 xx 加功能"——一句话里没有任何可实现的规格。P9（"分析用户行为"是目的语不是需求定义）常伴随，但归并本规则：目的语在这里的作用是掩盖事件全集的缺失。触发口径分歧的杀伤力最大：同名指标因触发时机不同而数值互斥，且这种错误在界面上完全不可见，只在数据消费方对数时爆雷。

## 误报注意

1. **埋点方案引用**："埋点方案见 tracking plan / 数据需求文档"——B1 以外部形式存在，需人工确认文档覆盖该流程；
2. **第三方 SDK 全托管**："接 xx 统计 SDK，自动采集"——SDK 自动采集有确定事件集，不命中（但自定义事件仍需定义，提示人工确认）；
3. **探索性单点**："就在支付按钮上埋一个点，看看点击率"——单事件 + 单目的明确，不命中。

## 漏报注意

1. **部分事件**：列了 3 个事件但漏了失败/取消分支——B1 出现打破命中，但事件全集不全（失败路径事件对漏斗分析关键），需按流程分支粒度核对；
2. **有事件无口径**："埋一个下单成功点"——B1 词出现但"什么时候算成功"未说，触发口径缺失仍是缺口（B1 打破命中但 B2 缺失变体）；
3. **埋点口语化**："把关键地方都埋上""该埋的都埋了"——"关键/该埋的"不构成事件枚举，应仍命中。
