# R-S29-P7 支付集成只定义支付发起路径

- **场景**：S29 第三方 API 集成　**标签**：[P7-流程断点](../../知识库/缺陷标签.md)
- **验证**：多解实现验证通过（2026-10-20，N=3，7 组冲突性假设：取消处置/失败补偿/生效路径/退款/对账/幂等/订单语义）

## 命中条件

**正向特征（须出现）**：

- **F1 第三方能力对接声明**："对接/接入/集成 + 第三方服务名（支付/登录/地图/短信…）+ 能力动作"类结构。
  - 例："**对接微信支付**，用户**可以在线支付**订单" → F1 成立；"接入高德地图，可以查周边" → F1 成立。
- **F2 发起路径描述**：用户侧主干动作（拉起支付/跳转授权/调起能力）有描述或隐含，路径是**单向 happy path**。
- **F2b 异常/逆向词出现**（与 F2 互斥，出现则 F2 不成立）：取消 / 失败 / 超时 / 退款 / 对账 / 回调丢失 / 补偿。

**反向特征（须全部不出现）**：

- **B1 中断路径**：取消 / 中途退出 / 超时未回调的订单处置说明。
  - 例："**15 分钟未支付自动关单**，关单后不可再付" → B1 出现。
- **B2 失败补偿**：回调丢失 / 异常时主动查单、重试、人工修复的说明。
  - 例："**每 30 秒主动查单补偿**，回调丢失自动修复" → B2 出现。
- **B3 逆向链路**：退款 / 对账 / 冲正的路径定义。
  - 例："**用户可申请退款，商家审核后原路退回**；每日自动对账" → B3 出现。

### 判定

```
(F1 ∧ F2 ∧ ¬B1 ∧ ¬B2 ∧ ¬B3) → 命中 R-S29-P7
```

判定式读法：**左边**（对接第三方，只说了用户怎么用起来）**同时右边**（中断、失败补偿、退款对账一个没提）→ 命中。F2b 与 F2 互斥：出现任何异常/逆向词说明已意识到分支，本规则不命中（可能命中更细规则）。

### 判定过程示例

**例 1（命中）**：

> "对接微信支付，用户可以在线支付订单。"

| 特征 | 结果 | 依据 |
|---|---|---|
| F1 | ✓ | "对接微信支付" |
| F2 | ✓ | "可以在线支付订单"单向主干 |
| B1 | ✗ | 取消/超时处置无 |
| B2 | ✗ | 失败补偿无 |
| B3 | ✗ | 退款/对账无 |

→ **命中**：实证显示 7 组互斥——取消处置（超时自动关单禁止再付 vs 永不关单随时重付 vs 每次重付生成新单——C 方案用户可能对同一订单付两次钱）、失败补偿（服务端定时查单秒级自愈 vs 仅用户返回时查一次 vs 纯等回调——回调丢失时 C 用户已扣款但订单永远"待支付"）、生效路径（回调驱动+前端轮询自动跳成功页 vs 返回即见 vs 手动刷新）、退款（用户端申请+审核+状态可查 vs 仅商户后台人工 vs 全走客服线下——订单内有无退款记录三案不同）、对账（每日逐笔+告警 vs 月度人工总额 vs 不做——掉单时 A 最迟 T+1 自愈，C 不投诉则永不发现）、重复回调幂等（强幂等 vs 弱幂等 vs 无幂等重复发货）、订单语义（支付推进通用状态机 vs 触发发货 vs 虚拟订单即完成）。

**例 2（不命中）**：

> "对接微信支付：15 分钟未付自动关单；回调丢失时每 30 秒主动查单补偿；用户可申请退款原路退回，每日自动对账。"

B1、B2、B3 全部出现 → **不命中**。

## 说明

本规则检测第三方集成类需求的**逆向与异常链路缺失**，与第三方类型无关（支付/登录/地图/短信集成均适用，支付最典型）。缺口实质：第三方能力集成 = 发起路径 + **中断处置 × 失败补偿 × 逆向链路（退款/对账）**。发起路径由第三方 SDK 约束（大家都会拉起支付页），趋同；逆向链路是纯决策空间——第三方文档提供了原料（关单接口、查单接口、对账单），但**何时用、要不要用、失败怎么办**全在己方设计。支付场景的特殊性：逆向链路缺口直接等于资金风险——重复回调无幂等 = 重复发货，无对账 = 掉单永不发现，取消不关单 = 重复付款。与 S14 的分界：S14 是业务流程自身的异常分支，S29 是**外部依赖引入的异常面**（回调可能丢、第三方可能超时、双方状态可能不一致），后者连"正常"都需要对账来确认。

## 误报注意

1. **第三方契约引用**："异常处理遵循微信支付最佳实践"——B1–B3 以外部文档形式存在，需人工确认其覆盖关单时机、退款入口等己方决策；
2. **一次性能力调用**：地图选点、短信发送等无状态、无资金风险的纯查询/通知类集成——逆向链路天然消失，降级为只检 B2（失败提示）；
3. **聚合支付平台兜底**："用 xx 聚合支付，退款对账走平台标准流程"——B3 由平台承载，不命中，需确认平台开通。

## 漏报注意

1. **逆向词出现无定义**："支持退款"出现 B3 词但入口/审核/时效未说——部分定义变体，逐路径核对（取消/补偿/退款/对账各自完整度）；
2. **异常藏在参数里**："下单 30 分钟有效期"——隐含超时关单（B1 弱形式），需识别时间参数背后的中断语义；
3. **多个第三方并存**：一条需求对接多个能力（支付+登录+分享）时，F2b/B 类判定须按能力逐个核对，一个能力定义完整不代表其他不缺。
