## S42 计算与精度

### CAND-043【已验证→沉淀规则】

（N=3：财务分账精度派 / 电商订单口径派 / 小团队 double 直算派）

> 订单金额按商品价格乘以数量，再乘以折扣自动计算。

**验证结论**：
- **冲突性假设（6 组，5 组三方互斥 + 1 组单边如实标注）**：① 舍入规则：A 银行家 HALF_EVEN（1.005→1.00）vs B 四舍五入 HALF_UP（→1.01）vs C toFixed 伪舍入（二进制实为 1.0049…→1.00 事实截断）——同一笔尾差订单三个系统三种总价，用户对比小票/发票差 1 分；② 运算路径与舍入时机：A 原文顺序全精度末次一次舍入 vs B 折后单价先落分再乘（round(2.55×0.95)=2.42×3=7.26）vs C double 直算（7.2675→7.27）——同一单 B 端 ¥7.26、A/C 端 ¥7.27；③ 折扣层级：A 逐行作用于行合计 vs B 订单总额（满折需凑单）vs C 改写折后单价——满 100 打折场景"多买一件才便宜"的购物体验完全不同；④ 多行尾差：A 尾差入"舍入损益"科目（Σ行≠总额账面体现）vs B 末行吸收（Σ行=总额但末行与手算不符）vs C 不分摊各行独立舍入——"明细加起来≠总价"直接引发扣错钱投诉；⑤ 权威口径：A 账务层（"账务 18.99，展示是 bug"）vs B 支付层（支付成功金额回写订单）vs C 展示层——展示 ¥18.98 实扣 ¥18.99 时三系统申诉处理三样；⑥ 精度载体【单边】：A long 分 vs B decimal（等价，剔除）真冲突为 C 的 double 浮点——0.1×3=0.30000000000000004 长尾，用户在账单页直接看见。
- **伪缺陷剔除**：BigDecimal/字段类型选型（A/B 等价）、币种字段（单一人民币）、折扣率表示法（0.85/85/8500 等价）、乘法交换次序纯数学等价部分、计算触发时机与审计快照、运费税费基数（范围外新增）。
- **P5 实证成立**——欠约束即歧义：公式人人读得懂，语义（舍入/路径/尾差/口径）人人读得不同，分位级差异用户 100% 可感知且有累积对账效应。已沉淀为 `场景/业务规则与数据/R-S42-P5.md`。

## S43 数据初始化与迁移

### CAND-044【已验证→沉淀规则】

（N=3：企业迁移全流程派 / 增长活跃优先派 / 小团队 CSV 导入派）

> 把老系统的会员数据迁移到新系统。

**验证结论**：
- **冲突性假设（5 组）**：① 迁移范围：A 全量会员一个不落（历史是合规资产）vs B 仅近 6 个月活跃（僵尸数据是负担）vs C 全量但无筛选标准——长期未登录的老会员发现账号被删除/无法登录；② 密码凭证：A 老哈希原样搬（新系统复用老算法，用户无感）vs B 强制全员重置（借机激活回流+清退羊毛党）vs C 首次登录旧密码验证后转新哈希——用户能否原密码直接登录还是被强制走找回；③ 历史资产：A 订单/积分/余额/等级全迁（账户连续性完整）vs B 只迁积分余额不迁订单（钱不能丢）vs C 视表结构好导就导——登录后积分、历史订单是否消失；④ 字段清洗：A 规范化清洗+合并重复账号+补全缺失 vs B 只迁核心字段其余丢弃 vs C 一对一照搬——收货地址等历史资料是否丢失、重复账号是否被合并；⑤ 并行策略：A 双跑双写+分批切流+老系统只读保留一周期 vs B 一次性切换老系统直接下线（避免双写泥潭）vs C 导完改 DNS 就切——切换窗口老系统是否可用、两端操作数据是否一致。
- **伪缺陷剔除**：ETL 工具/脚本、数据库品牌、批参数、对账技术手段（checksum vs 抽样）、C 的本地备份与 A 的回退预案（用户感知层趋同）、执行时间窗口。
- **P1 实证成立**——"迁移"日常语义默认"全部、无损、无感"，工程语义每维独立决策；分歧不可逆（老系统下线后历史订单找不回）。已沉淀为 `场景/业务规则与数据/R-S43-P1.md`。
