# R-S12-P1 导出需求未定义范围列集与上限

- **场景**：S12 导出　**标签**：[P1-不完整](../../知识库/缺陷标签.md)
- **验证**：多解实现验证通过（2026-10-20，N=3，5 组冲突性假设：数据范围/交付方式/列集/上限行为/格式实质）

## 命中条件

**正向特征（须出现）**：

- **F1 导出功能声明**："支持 / 需要 / 可以 + 导出 / 下载 / 输出"类结构。
  - 例："订单列表**支持导出** Excel" → F1 成立。
- **F2 导出对象为格式级表述**：仅指明格式（Excel / CSV / PDF）或仅说"导出 xx（实体）"，未定义导出**哪些数据、哪些列**。
  - 例："导出 **Excel**" → F2 成立（哪个范围的数据？哪些列？未说）。

F1 与 F2 须同时出现（导出声明 + 无范围列集定义）。

**反向特征（须全部不出现）**：

- **B1 范围定义**：导出数据范围的显式说明（当前筛选结果 / 当前页 / 全量 / 本人数据）。
  - 例："导出**当前筛选条件下**的订单" → B1 出现。
- **B2 列集定义**：导出字段列举，或"与列表列一致 / 含 xx 附加列"说明。
  - 例："导出列**与列表一致**，另附渠道列" → B2 出现。
- **B3 量级与交付定义**：数量上限 / 大数据量处理（异步任务 / 下载中心）/ 同步异步方式。
  - 例："超 **1 万条转异步任务**，下载中心获取" → B3 出现。

### 判定

```
(F1 ∧ F2) ∧ ¬B1 ∧ ¬B2 ∧ ¬B3 → 命中 R-S12-P1
```

判定式读法：**左边**（要支持导出，但只说了格式或实体）**同时右边**（范围、列集、量级交付全没定义）→ 命中。

### 判定过程示例

**例 1（命中）**：

> "订单列表支持导出 Excel。"

| 特征 | 结果 | 依据 |
|---|---|---|
| F1 | ✓ | "支持导出" |
| F2 | ✓ | 仅格式级（Excel），范围列集未说 |
| B1/B2/B3 | ✗ | 范围/列集/量级全无 |

→ **命中**：实证显示同一按钮被实现为"当前筛选全部匹配 + 异步下载中心 + 1 万分流"、"仅当前页 + 前端即点即下 + 无上限保护"、"默认全量表 + 一律异步 + 10 万截断限流"——运营一次导 10 万行，三个版本分别是正常拿文件、浏览器卡死、文件被截断首行提示。

**例 2（不命中）**：

> "订单列表支持导出：范围同当前筛选结果，列与列表一致另加备注列，超 1 万条转异步任务，下载中心取文件。"

B1（当前筛选）、B2（列表列+备注列）、B3（1 万条异步）出现 → **不命中**。

## 说明

本规则检测导出需求的**范围与量级要素缺失**，与导出领域无关（订单/用户/日志/报表导出均适用）。缺口实质：导出需求 = 数据范围 × 列集 × 量级与交付方式 × 格式。表面上"导出 Excel"是明确需求，实则三个用户可直接感知的维度全开放：导多少（几十行 vs 全库）、导什么列（精简 4 列 vs 含内部字段 user_id——后者已是数据泄露面）、怎么给（即点即下 vs 任务中心等通知）。"导出"自带 P4 隐含假设——需求方默认"导我看到的"，开发方默认"导表里有的"，两个默认集不交集。上限行为是隐形雷区：无上限保护的实现在大数据量下直接崩溃。

## 误报注意

1. **模板引用**："导出模板见附件 / 沿用现有导出模板"——B2 以外部形式存在，需人工确认模板覆盖；
2. **小数据确定性**：上下文明确数据量恒定小（如"导出本周排班表"，周知 <100 行）——量级风险不存在，降级为提示；
3. **主体不是导出**："导出功能顺便修个列宽"——导出已在别处定义，本需求主体是修列宽，不命中。

## 漏报注意

1. **有范围无列集**："导出当前筛选的订单"——B1 出现打破命中，但列集开放（内部字段是否泄出）仍是缺口；
2. **伪定义**："导出所有需要的字段""完整导出"——"需要/完整"不构成列集定义，应仍命中；
3. **格式陷阱**：B1–B3 齐备但实际生成 CSV 改 .xls 后缀（打开弹警告）——格式实质与声称不符，属实现质量问题非需求缺口，本规则不覆盖。
