# R-S09-P1 详情页展示内容未定义

- **场景**：S09 详情页　**标签**：[P1-不完整](../../知识库/无效需求标签.md)
- **验证**：多解实现验证通过（2026-10-20，N=3，5 组冲突性假设：页面定位/价格体系/核心交互/加载策略/辅助内容）

## 命中条件

**正向特征（须出现）**：

- **F1 详情实体声明**："做一个/开发/需要 + xx 详情页 / 详情 / 查看详情"类结构。
  - 例："**做一个**商品**详情页**" → F1 成立。
- **F2 内容指称为概括语**："详细信息 / 相关信息 / 完整信息 / 全部信息"类指代，或仅说"展示 xx"而无板块构成。
  - 例："展示商品的**详细信息**" → F2 成立（哪些信息？未定义）。
- **F3 使用者未声明**：未指明页面面向谁（消费者浏览 / 运营管理 / 内部查看）。
  - 例：通篇无"用户/买家/运营/管理员"定位语 → F3 成立。

F1 为必要条件，F2、F3 至少满足其一（F2+F3 同时出现最典型——"详细信息"的解读完全依赖使用者定位）。

**反向特征（须全部不出现）**：

- **B1 信息板块构成**：明确的板块/字段列举（基本信息 / 价格 / 库存 / 评价 / 参数 / 状态 / 操作日志等）。
  - 例："展示**基础信息、价格库存、评价、图文详情**四块" → B1 出现。
- **B2 使用者或页面定位**：面向买家 / 消费者 / 运营 / 管理员，或"购买页 / 管理页"类定位语。
  - 例："面向**买家**的购买决策页" → B2 出现。
- **B3 核心操作定义**：加购 / 购买 / 编辑 / 审核 / 上下架 等页面动作说明。
  - 例："支持**加购和立即购买**" → B3 出现。

### 判定

```
(F1 ∧ (F2 ∨ F3)) ∧ ¬B1 ∧ ¬B2 ∧ ¬B3 → 命中 R-S09-P1
```

判定式读法：**左边**（要做详情页，内容是概括语或没说给谁用）**同时右边**（板块构成、使用者定位、核心操作全没定义）→ 命中。

### 判定过程示例

**例 1（命中）**：

> "做一个商品详情页，展示商品的详细信息。"

| 特征 | 结果 | 依据 |
|---|---|---|
| F1 | ✓ | "做一个…详情页" |
| F2 | ✓ | "详细信息"概括指代 |
| F3 | ✓ | 无使用者定位 |
| B1/B2/B3 | ✗ | 板块/定位/操作全无 |

→ **命中**：实证显示三人分别实现为消费者购买决策页（主图+价格+SKU+评价+推荐+加购）、运营管理页（表单+状态+审核+操作日志）、纯数据接口（全字段透出）——一个卖货、一个管货、一个只有 JSON。

**例 2（不命中）**：

> "做一个面向买家的商品详情页，展示主图、价格、规格选择、图文详情和评价，支持加购和立即购买。"

B1（五板块列举）、B2（面向买家）、B3（加购/购买）出现 → **不命中**。

## 说明

本规则检测详情页需求的**信息板块与定位缺失**，与实体领域无关（商品/订单/工单/客户详情均适用）。缺口实质：详情页需求 = 使用者定位 × 信息板块全集 × 核心操作。"详细信息"是典型 P4 隐含假设的载体——每个人心中的"详细"都以自己常见的产品形态为参照，不做规定时页面会在"卖货还是管货"这一根本定位上分叉。使用者定位最隐蔽也最致命：它直接决定板块构成与操作集。

## 误报注意

1. **设计稿引用**："详情页见设计稿，板块以 Figma 为准"——B1 以外部形式存在，需人工确认设计稿覆盖度；
2. **既有页面复用**："在现有详情页加个分享按钮"——页面已存在，本需求主体是分享，不命中（应扫对应场景规则）；
3. **纯接口需求**："提供商品详情查询接口，返回全字段"——后端接口需求且明示全字段，不属页面场景，不命中。

## 漏报注意

1. **部分板块**：列了 3 个板块但缺价格/操作等关键项——B1 打破命中但构成不全，属"部分定义"缺口，需按板块粒度核对；
2. **有定位无板块**："做一个买家看到的商品页"——B2 出现使规则不命中，但 B1 单独缺失仍是缺口（定位给了、内容没给）；
3. **"详情"口语化**："点进去能看到这个东西的所有东西"——"所有东西"即详情语义，F1/F2 词表需覆盖口语表述。
