# requirement-quality

研究**需求的有效性**：什么样的需求描述拿去开发，会产出一个"能用但不符合预期"的结果。

本仓库沉淀了一套**内容无关的需求质量治理体系**：9 类无效需求标签 × 43 个场景 × 44 条可执行扫描规则。规则可直接喂给 AI（skill / clarifier）扫描任意需求文本——命中即指出信息缺口，不追问、不评分。

## 需求有效性治理体系

无效需求的定义：**描述与预期产出之间存在信息缺口**——开发只能自行假设，不同假设产出用户可感知的不同系统。治理体系由三层构成，层层收敛：

```
无效需求标签（9 类，无效形态的语言学分类）——"什么是无效"
      ×
场景（9 组 43 场景，需求世界的坐标）——"哪些场景无效"
      ↓
扫描规则（44 条，一格一文件的可执行判定）——"怎么检出"
```

### 第一层：无效需求标签——"什么是无效"

9 标签分三族（详见 [知识库/无效需求标签.md](知识库/无效需求标签.md)）：

| 族 | 标签 | 一句话 |
|---|---|---|
| **信息量缺陷**（写了但不够） | `P1-不完整` | 关键决策点缺失，开发必须自行假设 |
| | `P2-不可验证` | 无验收标准，"做到什么程度算完"缺失 |
| | `P3-主观模糊` | 主观形容词无量化，"要快""简洁易用" |
| | `P4-隐含假设` | 依赖未言明的上下文，"和现有系统一致" |
| **语言缺陷**（写了但会读歪） | `P5-歧义表述` | 一句多种解读；实证确立口径：**欠约束即歧义** |
| | `P6-不精确动词` | 动作动词无精确定义，"处理""支持" |
| **结构缺陷**（该有的段落没有） | `P7-流程断点` | 只写正常路径，失败/回退/撤销缺失 |
| | `P8-非原子` | 一条需求塞多个动作 |
| | `P9-范围失焦` | 边界未圈定，"通知用户""支持双端" |

三族即无效需求的三种无效机理：**信息不够**（读者缺料）、**语言有歧**（读者读歪）、**结构有洞**（该写的没写）。

> 无效形态可由词类预判（回测沉淀的规律）：程度/集合/体验形容词→P3，愿望陈述→P2，开放谱系动词→P9，判定负载词与私有共识→P4，欠约束公式→P5。

### 第三层：扫描规则——"怎么检出"

44 条规则全部落在 场景/ 目录，文件名 = 规则 ID = 矩阵格子坐标（如 `R-S01-P1.md` = S01 表单 × P1 不完整），一格一文件天然防重复。规则由**多解实现验证**产出（见方法论），命中即报告缺口——扫描 skill 不追问用户。

**43 场景已全量覆盖**（每组至少 1 条验证规则），已沉淀标签 7/9（余 P6/P8 待回测或定向验证驱动）。

## 方法论：多解实现验证法

一条规则入库前必须通过实证质检（详见 [知识库/调研方法论.md](知识库/调研方法论.md)）：

```
穷举场景（外部分类学交叉）→ 逐场景构造含预埋缺口的候选需求
    → 交给 3 个背景互补的独立实现者（AI 开发者人设）
    → 各自先输出实现假设清单（IMPLEMENTATION_NOTES 式）再交叉对比
    → 冲突性假设 ≥ 2 组（互斥且用户可感知）= 缺口实证成立 → 沉淀规则
    → 仅实现自由度差异（合理默认值）= 伪缺陷 → 剔除
```

- 每组冲突的具体分歧（A/B/C 各自选择）记录在 [测评集/](测评集/)（CAND-001~044，44 个候选的完整验证档案），是规则成立的证据；
- 规则不依赖具体案例成立——案例原文只存测评集，不进规则库。

## 双层闭环：合成铺场景体系，真实做校准

合成层与真实层互哺但物理分离（仓库里只有规则，真实需求留在回测记录）：

- **合成层**（已完成）：AI 构造候选 + 多解验证，铺满 43 场景——解决冷启动；
- **真实层**（进行中）：采集开源 issue / 外包平台 / 社区的真实需求（REAL-xxx，带来源 URL），逐条套用规则回测——命中 → 覆盖度 +1；信息完整反例 → 特异性证据；**盲区 → 修订规则或场景体系**。

**首轮回测结果**（2026-10-20，13 样本 14 判定单元）：命中 8 / 信息完整反例 4 / 盲区 2（特征收窄型、互斥误抑制型，均当日增强规则）/ 语言与语体边界 3。关键结论：**43 场景 × 9 标签经受住真实语料检验，无一例需要修订**——盲区全部落在规则特征工程层。详见 [覆盖矩阵.md](覆盖矩阵.md) 回测统计段。

## 规则格式

每条规则内容无关、自包含，固定段落：

```markdown
# R-<场景>-<标签> <缺陷一句话>

- **场景 / 标签 / 验证**（多解实现验证结论 + 回测增强记录，一行元数据）

## 命中条件
正向特征 F（须出现的结构，每个特征附一句话内联示例说明长什么样）
+ 反向特征 B（须不出现的词类，附例；互斥条款注明强度分级）
+ 布尔判定式（附读法）
+ 判定过程示例（一段命中 + 一段不命中，逐特征核对）

## 说明
缺口实质，与具体领域 / 字段内容无关

## 误报注意
不该命中却可能命中的情况（如外部引用、分期承诺、显式设计决策）

## 漏报注意
该命中却可能漏掉的情况（如部分定义、约束词歧义、弱边界词）
```

> 示例的定位：**特征的内联教学材料**（一句话示意结构，不限领域），不是需求案例——规则不引用具体案例，扫任何领域的需求都适用。

## 如何贡献

1. 新规则放入对应场景目录；文件名 = `R-<场景ID>-<标签ID>.md`，与矩阵格子一一对应；
2. 没有合适的场景目录时，先修订 [知识库/场景.md](知识库/场景.md) 再新建——发现场景体系未覆盖的场景时**先修场景体系再落目录**；
3. 规则须经多解实现验证（见 [调研方法论.md](知识库/调研方法论.md)）才能计入 [覆盖矩阵.md](覆盖矩阵.md)；候选与验证分歧记录在 `测评集/<场景组>.md`；
4. 同格已有规则时**增强**该规则（特征取并集、验证结论合并），不开新文件——回测触发的增强同样走此路径；
5. 真实样本回测条目用 `REAL-xxx` 编号同构追加，记录原文、来源 URL 与判定结论；
6. 规则只描述结构特征，**不引用具体需求案例**——扫任何领域的需求都适用。
