# R-S43-P1 数据迁移未定义范围与凭证处置

- **场景**：S43 数据初始化与迁移　**标签**：[P1-不完整](../../知识库/无效需求标签.md)
- **验证**：多解实现验证通过（2026-10-20，N=3，5 组冲突性假设：迁移范围/密码凭证/历史资产/字段清洗/并行策略）

## 命中条件

**正向特征（须出现）**：

- **F1 迁移意图声明**："把/将 + 老系统/旧系统/现有系统 + 数据 + 迁移/导入/搬迁/迁入 + 新系统"类结构。
  - 例："**把老系统的会员数据迁移到新系统**" → F1 成立；"**将现有数据导入**新平台" → F1 成立。
- **F2 迁移语义缺席**：迁什么（范围——全量/活跃/白名单）、凭证怎么处理（密码）、历史资产（积分/余额/订单）跟不跟着迁**全部缺席**。

**反向特征（须全部不出现）**——出现任何一个即不命中：

- **B1 范围界定**：迁移对象的范围说明（"全部会员"/"近 6 个月活跃"/"首批白名单名单见附件"）。
  - 例："迁移**近一年活跃会员**，其余归档不迁" → B1 出现。
- **B2 凭证策略**：密码/登录凭证的处理说明（原样迁移可免登录 / 强制重置 / 首登验证转换）。
  - 例："密码哈希**原样迁移**，用户无感切换" → B2 出现。
- **B3 历史资产处置**：积分/余额/订单等关联数据的迁移说明。
  - 例："积分余额**全额迁移**，历史订单**不迁**仅老系统可查" → B3 出现。

### 判定

```
(F1 ∧ F2) ∧ ¬B1 ∧ ¬B2 ∧ ¬B3 → 命中 R-S43-P1
```

判定式读法：**左边**（要迁移，就一句）**同时右边**（范围、凭证、历史资产一个没说）→ 命中。

### 判定过程示例

**例 1（命中）**：

> "把老系统的会员数据迁移到新系统。"

| 特征 | 结果 | 依据 |
|---|---|---|
| F1 | ✓ | "把老系统会员数据迁移到新系统" |
| F2 | ✓ | 迁移语义全缺席 |
| B1 | ✗ | 范围无 |
| B2 | ✗ | 凭证策略无 |
| B3 | ✗ | 历史资产无 |

→ **命中**：实证显示 5 组互斥——迁移范围（全量一个不落 vs 仅近 6 个月活跃 vs 全量无筛选标准——长期未登录的老会员发现账号被删除/无法登录）、密码凭证（老哈希原样搬免登录 vs 强制全员重置借机清退 vs 首登旧密码验证后转换——用户能否原密码直接登录还是被强制走找回）、历史资产（订单积分余额等级全迁 vs 只迁积分余额不迁订单 vs 视表结构可能不迁——登录后积分、历史订单是否消失）、字段清洗（规范化清洗+合并重复账号 vs 只迁核心字段 vs 一对一照搬——收货地址等历史资料是否丢失、重复账号是否被合并）、并行策略（双跑双写+分批切流 vs 一次性切换下线 vs 导完就切——切换窗口老系统是否可用、两端操作数据是否一致）。

**例 2（不命中）**：

> "迁移方案：全部会员数据迁入；密码哈希原样迁移免登录；积分余额全额迁移、历史订单不迁（老系统只读保留一年）；切换采用双跑一周后一次性切换。"

B1、B2、B3 全部出现 → **不命中**。

## 说明

本规则检测迁移类需求的**迁移语义缺失**，与数据对象无关（会员/订单/商品/工单数据迁移均适用）。缺口实质：迁移需求 = 范围 × 凭证 × 历史资产 × 清洗 × 并行切换——"迁移"一词在日常语境中默认"全部、无损、无感"，但工程语境中每个维度都是独立决策：范围上"只迁活跃"是增长视角的合理选择（僵尸数据是负担），凭证上"强制重置"是安全视角的合理选择（借机清退），但在用户感知层它们等于"账号被删了""密码被改了"。迁移的分歧还有**不可逆性**：切换完成后范围与资产的处置难以补救（老系统下线后历史订单再也找不回）。与 S39 的分界（已互相引用）：S43 是老系统数据**一次性搬入**新系统的项目行为，S39 是新版本**持续读得动**旧数据的能力——前者问"搬什么怎么切"，后者问"读多旧怎么迁"。

## 误报注意

1. **迁移方案文档承载**："迁移范围与切换方案见迁移专项文档"——B1–B3 以外部文档存在，不命中，需人工核对方案覆盖凭证与资产处置；
2. **无账号语义的纯数据**：迁移日志/商品目录等无登录凭证、无用户资产的数据——B2/B3 天然消失，降级为只检 B1 范围与清洗；
3. **灰度合并已定**：上下文已有明确决策记录（"已决定全员保留、密码强制重置"）——B1/B2 以决策记录形式存在，不命中。

## 漏报注意

1. **范围有资产无**："迁移全部会员"出现 B1 但积分余额/订单处置仍开放——部分定义变体，资产处置是最易漏的维度（钱不能丢，但需求常常只写"会员"）；
2. **"数据"泛指迷惑**："迁移会员相关全部数据"——"相关"未枚举（含订单？含浏览记录？），B3 弱出现需按资产类型逐项核对；
3. **初始化类变体**："新系统上线要有基础商品数据"——初始化（造新数据）与迁移（搬旧数据）结构同构，F1 需覆盖"初始化/预置/导入基础数据"表述（无凭证维度但有范围与来源语义）。
