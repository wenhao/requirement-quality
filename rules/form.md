# 规则库：数据录入组（S01–S04）

> 扫描规则库——**skill / clarifier 的唯一消费源**，内容无关的结构化检测规则。每条规则对应矩阵一个格子（场景 × 标签），ID 即格子坐标。案例不进入规则（案例在 `cases/`，仅作人读证据与规则回归测试）。

## 规则格式说明

每条规则包含：命中条件（正向特征 F / 反向特征 B）、判定逻辑、说明、误报注意（什么情况不该命中却可能命中）、漏报注意（什么情况该命中却可能漏掉）、验证依据与关联案例。

## R-S01-P1 表单字段规则缺失

- **场景**：S01 表单（新增/编辑）　**标签**：P1-不完整

### 命中条件

**正向特征（须出现）**：
- **F1 实体声明**：出现"做一个 / 开发一个 / 需要 / 想要 + 页面 / 功能 / 模块 / 表单"类实体引入结构；
- **F2 内容枚举或动作对**（与 F1 至少满足其一，两者同时出现最典型）：
  - F2a 字段枚举："包括 / 包含 / 含有 + 名词并列清单"（顿号、逗号、和/与连接）；
  - F2b 动作对："可以 / 支持 + 动词 + 和 + 动词"（如"添加和编辑"、"查询和导出"）。

**反向特征（须全部不出现）**：
- **B1 约束词**：必填 / 选填 / 可选 / 格式 / 长度 / 上限 / 下限 / 校验 / 正则 / 限制 / 非空；
- **B2 平台词**：Web / H5 / 小程序 / App / 后台 / PC / 移动端 / 端上；
- **B3 失败路径词**：失败 / 异常 / 重试 / 重复提交 / 网络错误。

### 判定

```
(F1 ∧ (F2a ∨ F2b)) ∧ ¬B1 ∧ ¬B2 ∧ ¬B3 → 命中 R-S01-P1
```

### 说明

本规则检测的是**信息缺口结构**，与枚举的具体字段无关：用户信息表单、商品录入表单、收货地址表单，只要"列了东西 + 没有任何规则性约束"即命中。缺口的实质是开发必须自行假设字段级规则（必填性/格式/长度/字符集）与关键决策点（平台/数量上限/失败处理），不同假设产出用户可感知的 different 系统。

### 误报注意

1. **外部引用**：需求含"规则详见附件 / 校验规则见 XX 文档"时不命中——信息可能在外部文档中，缺口只是"未内联"，需人工确认文档是否真实覆盖；
2. **明确的后续文档承诺**："一期先做界面，校验规则二期补充"属于分期决策而非缺口，不命中；
3. **纯展示型表单**：若上下文表明表单不落库（如筛选表单），字段规则缺失的影响面不同，降级为提示而非缺陷。

### 漏报注意

1. **部分约束**：出现个别约束词但只覆盖部分字段（"手机号必填"，其余字段未说）时，B1 被稀释导致漏报——扫描时应按字段粒度核对：枚举的每个字段是否都有规则归属（显式约束或显式豁免）；
2. **约束词歧义**："支持"既可作为动作对连接词（F2b）也可能是约束表述（"支持 20 条以内"），需按语义而非词面分类；
3. **隐式枚举**：字段不并列而是散落在句中（"用户填写姓名后输入手机号…"）时 F2a 不触发，需先做实体抽取再套规则。

### 验证依据

CAND-001（收货地址表单，结构等价）多解实现验证通过（2026-10-20，N=3）：5 处用户可感知分歧（布局/姓名长度/地址下限/+86 处理/Emoji 限制）。详见 [cases/form/no-field-validation.md](../cases/form/no-field-validation.md)。
