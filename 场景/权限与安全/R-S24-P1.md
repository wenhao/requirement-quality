# R-S24-P1 验证码登录未定义账号体系边界

- **场景**：S24 登录/认证　**标签**：[P1-不完整](../../知识库/缺陷标签.md)
- **验证**：多解实现验证通过（2026-10-20，N=3，5 组冲突性假设：未注册行为/老账号冲突/封禁账号/多设备策略/前置人机校验）

## 命中条件

**正向特征（须出现）**：

- **F1 认证方式声明**："通过/使用/支持 + 手机号/邮箱 + 验证码 + 登录/注册/验证"类结构。
  - 例："用户**可以通过手机号验证码登录**" → F1 成立。
- **F2 账号边界缺席**：需求止于认证动作本身，未注册用户的行为、与存量账号的关系、账号状态约束**全部缺席**。

**反向特征（须全部不出现）**——出现任何一个即不命中：

- **B1 未注册行为定义**：手机号未注册时发生什么（自动注册 / 提示先注册 / 拒绝）。
  - 例："未注册手机号验证通过后**自动创建账号**" → B1 出现。
- **B2 账号关系定义**：与已有账号（密码账号/邮箱账号/第三方账号）的合并或绑定规则。
  - 例："已有邮箱账号的用户首次验证码登录时**引导绑定原账号**" → B2 出现。
- **B3 账号状态约束**：封禁/停用/离职账号能否凭验证码登录。
  - 例："**封禁账号**验证通过也拒绝登录" → B3 出现。

### 判定

```
(F1 ∧ F2) ∧ ¬B1 ∧ ¬B2 ∧ ¬B3 → 命中 R-S24-P1
```

判定式读法：**左边**（支持验证码登录，就一句）**同时右边**（未注册行为、账号关系、状态约束一个没说）→ 命中。

### 判定过程示例

**例 1（命中）**：

> "用户可以通过手机号验证码登录。"

| 特征 | 结果 | 依据 |
|---|---|---|
| F1 | ✓ | "通过手机号验证码登录" |
| F2 | ✓ | 全文一句，账号边界全缺席 |
| B1 | ✗ | 未注册行为无 |
| B2 | ✗ | 老账号关系无 |
| B3 | ✗ | 封禁约束无 |

→ **命中**：实证显示 5 组互斥——未注册行为（发码+静默建号受限 vs 不发码报"联系管理员" vs 建号直进全功能——未注册用户在 B 根本收不到短信）、存量老账号（检测冲突弹绑定引导 vs 通道仅对预绑定账号开放 vs 不检测直接新建平行账号——老用户在 C 被静默送进空账号，历史数据"消失"）、封禁账号（拒绝并记日志【A/B 趋同】vs 无状态概念照常放行）、多设备（多端并行+设备管理 vs 单会话踢旧设备 vs 长效 token 无管理）、前置人机校验（滑块+日发码上限 vs 无【B/C 趋同】）。

**例 2（不命中）**：

> "手机号验证码登录：未注册手机号验证通过后自动注册；已有密码账号首次使用时引导绑定；封禁账号拒绝登录。"

B1、B2、B3 全部出现 → **不命中**。

## 说明

本规则检测认证类需求的**账号体系边界缺失**，与认证方式无关（验证码/扫码/第三方 OAuth 登录均适用）。缺口实质："验证码登录"约束的是一次认证动作，但登录入口是账号体系的闸门——谁允许有账号（未注册行为）、账号如何互通（与存量账号的合并）、账号的生命周期状态（封禁/离职）全部经过这道闸门，却未被提及。实证中最高风险的一组：老账号静默分裂——同一人在 C 方案下被创建平行新账号，历史数据"消失"，用户可感知且难以自助恢复。验证码本身的规格（位数/有效期/锁定）三方向合理默认收敛，被剔除为伪缺陷——冲突集中在账号语义而非验证码参数，这正是"该需求缺口在体系边界不在动作细节"的证据。

## 误报注意

1. **账号体系外部承载**："用集团统一账号中心登录"——B1–B3 由账号中心定义，本系统无需重复，不命中；
2. **纯员工系统**：上下文表明账号由 IT 预建（无自注册场景）——B1 由组织流程承载，需人工确认；
3. **POC/内部工具**：明确无安全要求的演示场景，账号边界缺失降级为提示。

## 漏报注意

1. **部分边界**："未注册自动注册"出现 B1 但老账号合并/封禁仍开放——部分定义变体，逐要素核对；
2. **验证码规格诱惑**：写了"6 位验证码，5 分钟有效"不等于定义了账号边界——规格词出现不应误判为 B 类特征，B1–B3 只认账号语义；
3. **口语化**："拿手机号收个码就能登"——F1 词表需覆盖口语认证表述。
