# R-S40-P9 范围声明用"核心/后续"替代功能清单

- **场景**：S40 范围/优先级　**标签**：[P9-范围失焦](../../知识库/无效需求标签.md)
- **验证**：多解实现验证通过（2026-10-20，N=3，8 组冲突性假设：核心圈定口径/优惠券取舍/评价取舍/客服取舍/报表取舍/后续时间锚/变更处理/争议裁决）

## 命中条件

**正向特征（须出现）**：

- **F1 范围分期声明**："本期/一期/先做 + 核心/主要/重点 + 功能"，"其他/剩余/其余 + 后续/下期/迭代"类分期结构。
  - 例："**本期先做核心功能**，**其他功能后续迭代**" → F1 成立。
- **F2 分期无清单**："核心"无功能枚举或圈定口径（最小闭环/合同清单/演示路径），"后续"无时间锚点——分期声明以形容词替代了清单。

**反向特征（须全部不出现）**——出现任何一个即不命中：

- **B1 核心清单**：本期功能的明确枚举或可核对的圈定依据（"本期做 A/B/C"/"以合同 SOW 为准"）。
  - 例："本期做**下单、支付、订单管理**三项" → B1 出现。
- **B2 后续锚点**：被移出功能的去向与时间承诺（"其余进二期排期"/"backlog 按数据决定，上线后一个月评审"）。
  - 例："其余功能**列入二期，里程碑见排期表**" → B2 出现。
- **B3 变更裁决依据**：中途加需求/范围争议的处理规则。
  - 例："范围变更**走变更单审批**，验收以**签字版清单**为准" → B3 出现。

### 判定

```
(F1 ∧ F2) ∧ ¬B1 ∧ ¬B2 ∧ ¬B3 → 命中 R-S40-P9
```

判定式读法：**左边**（宣布了分期，但哪期做什么没列清单）**同时右边**（核心清单、后续锚点、变更依据一个没出现）→ 命中。

### 判定过程示例

**例 1（命中）**：

> "本期先做核心功能，其他功能后续迭代。"

| 特征 | 结果 | 依据 |
|---|---|---|
| F1 | ✓ | "先做核心/后续迭代"分期结构 |
| F2 | ✓ | 无清单无锚点 |
| B1 | ✗ | 核心清单无 |
| B2 | ✗ | 后续去向无 |
| B3 | ✗ | 变更依据无 |

→ **命中**：实证显示 8 组互斥——核心圈定口径（最小可收费闭环 2 个功能 vs 合同承诺 5 个 vs 全做简化版 6 个——首版功能数量 2/5/6，用户一眼可见）、优惠券（不做无入口 vs 完整版 vs 仅满减——结账时有无抵扣入口）、评价（不做 vs 只读预置 vs 可写）、客服（不做 vs 不做 vs 留言板——用户有无求助入口）、报表（不做查库 vs 完整看板 vs 简单统计页——老板看数据求人还是点页面）、后续锚点（无期限 backlog vs 二期合同时间表 vs 下版即增强——被砍功能何时能用上的承诺完全不同）、变更处理（一律拒绝 vs 变更单签字可插入 vs 顺手做掉）、争议裁决（真实交易跑通即过 vs 合同清单逐项核验 vs 全流程点通即过——同一份交付物三种相反结论）。

**例 2（不命中）**：

> "本期范围：下单、支付、订单管理三项；优惠券、评价、客服列入二期（里程碑见排期表）；范围变更走变更单，验收以签字版功能清单为准。"

B1、B2、B3 全部出现 → **不命中**。

## 说明

本规则检测范围声明的**分期词替代清单**缺陷，与项目类型无关（MVP/企业交付/外包均适用）。缺口实质：范围声明的价值恰恰在于**可裁决**——明确做什么不做什么；"先做核心功能"用形容词替代清单后，裁决权完全下放：MVP 派按"最小收费闭环"切出 2 个功能，交付派按"合同演示效果"切出 5 个，多面手按"架构打通"全做简化版——三种切法都真诚地执行了"核心"，首版交付物却相差 3 倍。范围失焦的代价在此场景最直接：它不是某个功能的偏差，而是**整个项目边界**的漂移——验收时同一份交付物得到通过/不通过/勉强通过三种裁决。本场景是 P9 的根因案例：S19（消息）/S23（权限）/S32（多端）/S37（国际化）的范围失焦都是功能内名词失焦，S40 是**范围声明本身失焦**——写范围的地方都失焦，是失焦的源头形态。

## 误报注意

1. **清单在前文**：上下文已有带优先级标注的功能清单，本句仅是总结性表述——B1 以引用形式存在，跨段落核对后不命中；
2. **合同/SOW 承载**："范围以合同附件功能清单为准"——B1/B3 由商务文档承载，不命中，需确认合同清单含变更条款；
3. **探索型项目声明**："做什么等验证后再定"是显式的滚动范围决策（如用户调研期）——范围刻意开放是决策而非缺口，不命中。

## 漏报注意

1. **核心有锚点无清单**："核心指合同内功能"——B1 以引用弱出现但具体项仍需翻合同，且 B2/B3 常态缺失，按三要素核对；
2. **清单有变更无裁决**："本期做 A/B/C"出现 B1 但中途加需求的处理（B3）未说——部分定义变体，范围争议仍无裁决依据；
3. **口语化分期**："先把主要的搞出来，别的以后再说"——F1 词表需覆盖口语分期表述。
