# R-S18-P1 防重需求未定义重复口径与拦截层级

- **场景**：S18 并发与幂等　**标签**：[P1-不完整](../../知识库/无效需求标签.md)
- **验证**：多解实现验证通过（2026-10-20，N=3，6 组冲突性假设：拦截层级/重复判定/拦截后行为/超时重点/窗口时长/重复粒度）

## 命中条件

**正向特征（须出现）**：

- **F1 防重意图声明**："防止 / 避免 / 禁止 + 重复 + 提交/下单/请求/点击"或"保证幂等 / 防止并发"类结构。
  - 例："提交订单时**要防止用户重复提交**" → F1 成立；"**保证接口幂等**，不能多扣款" → F1 成立。
- **F2 防重口径缺席**：什么算"重复"的判定标准（时间窗口 / 内容相同 / 用户在途唯一 / 连击）**未出现**。
- **F3 拦截行为缺席**：撞上重复后的行为（静默返回原单 / 提示 / 报错）**未出现**。

F1 必须出现；F2 与 F3 至少其一缺席时即典型（两者全缺席最典型）。

**反向特征（须全部不出现）**——出现任何一个即不命中：

- **B1 重复判定口径**：时间窗（"5 秒/5 分钟内"）、内容指纹（"相同内容的请求"）、在途唯一（"存在未完成订单时"）任一说明。
  - 例："**5 秒内**相同请求视为重复" → B1 出现。
- **B2 拦截层级与手段**：前端置灰/防抖、后端幂等 token/唯一索引的指定。
  - 例："后端用**幂等 token**，前端按钮**点击后置灰**" → B2 出现。
- **B3 拦截后行为**：被拦截时用户看到什么（返回原单 / "请勿重复提交"提示 / 报错）。
  - 例："重复请求**返回原订单号**" → B3 出现。

### 判定

```
F1 ∧ (¬F2 ∨ ¬F3) ∧ ¬B1 ∧ ¬B2 ∧ ¬B3 → 命中 R-S18-P1
```

判定式读法：**左边**（声明了防重意图，且重复口径或拦截行为至少一个没说）**同时右边**（口径、层级、行为均未以任何形式出现）→ 命中。实际判定中 F2/F3 与 B1/B3 是同一信息的一体两面（口径缺席 = 无 B1 词），多数情况简化为 F1 ∧ ¬B1 ∧ ¬B2 ∧ ¬B3。

### 判定过程示例

**例 1（命中）**：

> "提交订单时要防止用户重复提交。"

| 特征 | 结果 | 依据 |
|---|---|---|
| F1 | ✓ | "要防止用户重复提交" |
| F2 | ✓ 缺席 | 什么算重复全无 |
| F3 | ✓ 缺席 | 拦住后怎样全无 |
| B1/B2/B3 | ✗ | 口径/层级/行为均无 |

→ **命中**：实证显示 6 组互斥——拦截层级（服务端强幂等 vs 前端+后端双层 vs 仅前端防抖，弱网/脚本场景下 C 用户产生两笔订单两次扣款）、重复判定（在途订单唯一 vs 内容相同+时间窗 vs 连击判定，用户想下不同地址的新单在 A 被拦截 B/C 放行）、拦截后行为（静默返回原单 vs 提示勿重复 vs 静默吞掉，连点两次后三种命运）、超时重点（幂等返回原单 vs 拦截提示 vs 正常建新单）、窗口时长（在途存续期 vs 5 分钟 vs 1~2 秒）、重复粒度（不看内容全拦 vs 同内容才拦 vs 只防连击）。

**例 2（不命中）**：

> "提交订单时防止重复：前端按钮点击后置灰至接口返回，后端以用户+订单内容指纹在 5 分钟内去重；重复请求返回首次的订单号并提示。"

B1（5 分钟内容指纹）、B2（前端置灰+后端去重）、B3（返回原单+提示）全部出现 → **不命中**。

## 说明

本规则检测防重/幂等类需求的**判定口径缺失**，与操作类型无关（下单/支付/表单提交/点赞均适用）。缺口实质：防重需求 = 重复判定口径 × 拦截层级 × 拦截后行为。"防止重复提交"是意图声明而非规格——"重复"本身有至少三种互斥口径：连击口径（防手抖）、内容口径（防相同请求）、在途口径（防一单多开），三者保护范围依次扩大、误伤也依次增加；拦截后行为决定用户感知（静默合并体验最顺但掩盖了重复事实，报错最诚实但体验最差）。更关键的是拦截层级：仅前端防护在弱网重试、页面刷新、脚本直连下全部失效——是否要求服务端幂等是资金安全级的决策，不能默认下放。原文越短，这三个维度越全部开放。

## 误报注意

1. **平台级幂等惯例**："所有写接口走统一幂等网关"——B2 以平台机制形式存在，需人工确认网关覆盖本操作且口径明确；
2. **上游已有防重**：上下文表明该操作链路的更上游已防重（如支付渠道幂等），本层不重复定义不命中；
3. **明确接受重复**："允许重复下单，去重交给运营后台合并"——这是显式决策而非缺口，不命中。

## 漏报注意

1. **只给口径没给行为**："5 秒内算重复"出现 B1 词但拦住后返回什么没说——部分定义变体，需逐维度核对；
2. **只给前端手段**："按钮点击后置灰"出现 B2 词但服务端是否防重（弱网/脚本场景）未说——B2 的部分出现应按层级拆分核对（前端层/服务端层各自是否有定义）；
3. **口语化防重**："别让人连点两下下两单"——F1 的词表需覆盖口语表述；
4. **防重藏在其他需求里**：批量导入/支付回调等需求附带"别重复导入/别重复记账"——防重意图以子句形式存在，扫描需跨子句识别 F1 结构。
