# R-S28-P4 合规要求隐含法域与义务集假设

- **场景**：S28 隐私与合规　**标签**：[P4-隐含假设](../../知识库/无效需求标签.md)
- **验证**：多解实现验证通过（2026-10-20，N=3，7 组冲突性假设：法域解释/同意机制/主体权利/保留删除/第三方告知/未成年人/政策版本）

## 命中条件

**正向特征（须出现）**：

- **F1 合规目标声明**："符合/满足/遵守 + 法律法规/监管要求/行业标准/xx 保护要求/合规"类结构。
  - 例："系统**要符合个人信息保护的要求**" → F1 成立；"**满足合规要求**" → F1 成立。
- **F2 要求来源裸奔**："要求"由哪个法规/标准/法域定义**未指明**（不点名个保法/GDPR/等保/行业规范，或点名但不落义务条款），具体义务清单缺席。

**反向特征（须全部不出现）**——出现任何一个即不命中：

- **B1 法规标准指明**：具体法规/标准/条款的指明（"按个保法第 xx 条"/"通过等保三级测评"）。
  - 例："符合**《个人信息保护法》**关于知情同意和最小必要的规定" → B1 出现。
- **B2 义务清单落地**：具体义务项的枚举（同意机制/注销入口/数据导出/保留期限等可执行条款）。
  - 例："需实现**用户同意、账号注销、数据导出**三项功能" → B2 出现。
- **B3 合规范围界定**：适用的业务/数据/地域范围界定（"仅国内业务"/"欧盟用户数据"）。
  - 例："**仅对欧盟用户**适用 GDPR 义务" → B3 出现。

### 判定

```
(F1 ∧ F2) ∧ ¬B1 ∧ ¬B2 ∧ ¬B3 → 命中 R-S28-P4
```

判定式读法：**左边**（要合规，但合规按哪套要求没说）**同时右边**（法规指明、义务清单、适用范围一个没出现）→ 命中。

### 判定过程示例

**例 1（命中）**：

> "系统要符合个人信息保护的要求。"

| 特征 | 结果 | 依据 |
|---|---|---|
| F1 | ✓ | "符合个人信息保护的要求" |
| F2 | ✓ | "要求"来源未指明 |
| B1 | ✗ | 无法规指明 |
| B2 | ✗ | 无义务清单 |
| B3 | ✗ | 无范围界定 |

→ **命中**：实证显示 7 组互斥——法域解释（个保法全量 vs GDPR vs 行业通行做法——B 的注册流程多出跨境传输授权节点和 DPO 联系页）、同意机制（分项勾选+敏感单独同意 vs opt-in 可随时撤回 vs 注册即一揽子同意——拒绝营销授权后 B 正常用、A 部分功能不可用、C 没有拒绝入口）、主体权利（查询/更正/删除/注销/导出五项 vs GDPR 六项+30 天时限 vs 仅注销+人工客服——设置页有无"导出我的数据"按钮三案不同）、保留删除（法定期限届满自动删 vs 请求驱动擦除 vs 永久保留仅逻辑标记——注销后能否"找回"账号）、第三方告知（清单+单独同意弹窗 vs 名单+随时反对开关 vs 一句话概括——能否看到第三方名单并关闭某类共享）、未成年人（14 岁+监护人同意 vs 16 岁+强制验证 vs 声明免责——注册是否强制填出生日期）、政策版本（重大变更阻断式重新同意【A/B 趋同】vs 公告+继续使用视为同意——更新后是否被强制弹窗）。

**例 2（不命中）**：

> "系统需符合《个人信息保护法》要求（仅国内业务）：实现注册分项同意、账号注销、个人信息导出三项功能；隐私政策重大变更时阻断式重新取得同意。"

B1、B2、B3 全部出现 → **不命中**。

## 说明

本规则检测合规类需求的**法域义务隐含假设**，与合规主题无关（个人信息/数据安全/行业监管均适用）。缺口实质：合规需求 = 法域（按哪套要求）× 义务集（哪些条款落到系统功能）× 范围（对哪些数据/用户生效）。"符合要求"预设了"要求"众所周知——但个保法、GDPR、等保的义务集互不包含：同意模式（一揽子 vs 分项 vs 可撤回）、权利落地（注销够不够 vs 须可携带）、数据生命周期（保留 vs 擦除）各不相同，同一句话被解释为三套互斥的功能清单。合规需求的特殊风险在于**验收方是监管不是产品**：功能分叉不只是体验差异，漏项即违规——按"行业通行做法"实现的系统在个保法执法检查下可能直接不达标。写作者通常默认"国内业务当然按个保法"，但出海、外资、多地域业务下该假设恰恰最常失效。

## 误报注意

1. **行业合规框架成熟**：上下文已指明行业（"三甲医院信息系统"）且行业标准义务明确——B1/B2 由行业默认承载，需人工确认无特殊叠加义务；
2. **法务团队承接**："合规义务由法务输出清单，系统按清单实现"——义务集外部承载，本条需求不适用，但需核对清单是否已交付；
3. **明确豁免场景**：内部测试环境/不采集个人信息的系统——个人信息保护要求不适用，不命中。

## 漏报注意

1. **点名法域无义务清单**："要符合个保法"——B1 出现但个保法条款数十条，哪些落到本期系统（B2）仍开放，部分定义变体，需按义务项核对；
2. **合规词泛化**："安全合规""数据合规"——比"个人信息保护"更泛的词，法域空间更大，F2 判定应更从严；
3. **义务藏在散句**：全文散见"用户可注销账号""隐私政策要弹窗"——B2 以散落形式存在，需汇总核对是否构成完整义务清单，散句不完整时仍应命中。
