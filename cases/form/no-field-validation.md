# 表单场景未定义字段校验规则

## 原始需求

> 做一个用户信息登记表单，包含姓名、手机号、邮箱，用户填完提交后保存到系统里。

## 缺陷分析

需求只描述了"有哪些字段"和"提交保存"，完全没有定义校验规则，开发只能自行假设：

- 哪些字段**必填**、哪些可以留空？
- 手机号/邮箱的**格式校验**怎么做？格式错误时是阻断提交还是提交后提示？
- 姓名**长度上限**？是否允许 emoji、生僻字、空格？
- 手机号是否需要**验证码校验**（真实存在性）还是仅格式校验？
- 提交失败（网络异常/重复提交）时表单状态如何处理？

不同的假设会产出完全不同的表单：宽松实现会脏数据入库，严格实现可能把合理输入也拦下，返工几乎不可避免。

**多解实现验证旁证**（同格候选 CAND-001"收货地址表单"，结构与本样本等价：字段枚举 + 添加/编辑动作，无任何规则）：3 个独立 AI 开发者（React 后台 / Vue H5 / Java 后端人设，互不知晓）各自实现，出现 5 处用户可感知分歧——表单布局（弹窗 vs 独立页，根因是目标平台未定义）、姓名长度上限（25 vs 20 字符）、地址下限（≥5 字 vs 无）、手机号 +86 处理（拒绝 vs 归一化剥离）、Emoji 限制（仅后端背景开发者提出防面单乱码）。分歧即信息缺口的实证。

## 应补充的内容

1. 目标平台与形态：Web 后台 / H5 / 小程序，表单承载形式（弹窗 / 抽屉 / 独立页）；
2. 字段级校验表：每个字段的必填性、格式规则（正则/格式说明）、长度上下限、字符集限制；
3. 校验时机与提示方式：失焦即校验 or 提交时统一校验，错误提示展示位置；
4. 是否需要短信/邮箱验证码等真实性校验；
5. 重复提交、网络失败时的交互与数据一致性要求；
6. 验收标准：给出合法/非法输入的示例清单。
