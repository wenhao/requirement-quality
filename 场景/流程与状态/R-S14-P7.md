# R-S14-P7 审批流只定义正向路径

- **场景**：S14 业务流程/审批流　**标签**：[P7-流程断点](../../知识库/无效需求标签.md)
- **验证**：多解实现验证通过（2026-10-20，N=3，分歧：驳回后重提（重新发起 vs 续审 vs 无所谓）/超时处理（提醒+转交 vs 可配置 vs 仅提醒）/撤回条件全分歧；正向路径趋同）

## 命中条件

**正向特征（须出现）**：

- **F1 流程实体声明**："做一个/需要 + 流程/审批/工作流"类结构。
  - 例："**做一个**请假**审批流程**" → F1 成立。
- **F2 正向路径描述**：描述了主干流转（提交 → 审批 → 通过/完成），路径是**单向 happy path**。
  - 例："员工提交请假申请后走审批，**审批通过后完成**" → F2 成立。
- **F2b 分支/异常词出现**（与 F2 互斥，出现则 F2 不成立）：驳回 / 拒绝 / 不通过 / 撤回 / 取消 / 超时 / 转办 / 退回。

**反向特征（须全部不出现）**——即 F2b 类词一个都不出现：

- **B1 驳回路径**：驳回 / 不通过 / 拒绝 + 后续行为定义（重新提交 / 修改 / 终止）。
- **B2 中断路径**：撤回 / 取消 + 允许条件。
- **B3 超时路径**：超时 / 逾期 + 处理方式（提醒 / 转交 / 自动通过）。

### 判定

```
(F1 ∧ F2 ∧ ¬B1 ∧ ¬B2 ∧ ¬B3) → 命中 R-S14-P7
```

判定式读法：**左边**（定义了流程主干）**同时右边**（驳回、撤回、超时三种异常路径一个没提）→ 命中。F2b 与 F2 互斥：只要出现任何一个异常词，就说明需求已意识到分支，本规则不命中（但可能命中更细的规则）。

### 判定过程示例

**例 1（命中）**：

> "做一个请假审批流程，员工提交请假申请后走审批，审批通过后完成。"

| 特征 | 结果 | 依据 |
|---|---|---|
| F1 | ✓ | "做一个…审批流程" |
| F2 | ✓ | "提交→审批→通过后完成"单向主干 |
| B1 | ✗ | 全文无"驳回/不通过" |
| B2 | ✗ | 无"撤回/取消" |
| B3 | ✗ | 无"超时" |

→ **命中**：实证显示正向路径三人趋同（提交→上级审批→通过），但驳回重提、超时、撤回的行为完全分歧（重新发起 vs 可配置续审 vs 只做提醒）。

**例 2（不命中）**：

> "请假审批：提交后直属上级审批；驳回时可修改后重新提交，重新走完整流程；超 48 小时未审批自动提醒。"

B1（驳回+重新提交定义）、B3（超时+提醒）出现 → F2 被打破，**不命中**。

## 说明

本规则检测流程类需求的**异常路径缺失**，与流程领域无关（请假/报销/合同/发布审批均适用）。缺口实质：流程需求 = 正向路径 + 异常路径（驳回/撤回/超时/转办）。正向路径因业务常识约束容易趋同，异常路径是纯决策空间——不做规定时开发只能自行设计，而这些路径恰是用户感知最强的部分（"驳回了居然不能改了重新提？"）。

## 误报注意

1. **流程图引用**："异常分支见流程图"——B1/B2/B3 以外部形式存在，需人工确认流程图覆盖度；
2. **明确免审批**："金额 500 元以下自动通过，无需审批"——这不是异常路径缺失而是业务规则，不命中；
3. **单向终态流程**：注册激活、消息推送等天然无驳回分支的流程——F1 的"流程/审批"词表应限定在含人工决策节点的流程，自动流转类不适用。

## 漏报注意

1. **异常词出现但无定义**："驳回后重新提交"出现 B1 词但"重新提交后从头审还是续审"未说——词出现打破反向特征，但定义不完整，属"部分定义"变体（F1 ∧ B1词 ∧ ¬B1定义），需语义级判定；
2. **部分异常覆盖**：只写了驳回没写超时——规则因 B1 出现不命中，但 B2/B3 缺失仍在，可命中放宽版（¬B2 ∧ ¬B3 子集判定）；
3. **异常藏在口语里**："领导不批就打回来"——"打回来"是驳回的口语表述，B1 词表需覆盖。
