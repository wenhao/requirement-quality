# R-S19-P9 通知需求核心名词未圈定范围

- **场景**：S19 提示/通知　**标签**：[P9-范围失焦](../../知识库/无效需求标签.md)
- **验证**：多解实现验证通过（2026-10-20，N=3，6 组冲突性假设：消息所指/渠道/触发时机/点击落地/通知对象/免打扰频控）

## 命中条件

**正向特征（须出现）**：

- **F1 通知意图声明**："有/收到/新增 + 消息/通知/提醒 + 时/后 + 通知/提醒/告知 + 用户/xx"类结构，或"支持消息通知功能"。
  - 例："**有新消息时通知用户**" → F1 成立；"**支持消息推送**" → F1 成立。
- **F2 核心名词裸奔**："消息"（通知什么）与"用户"（通知谁）至少一个以泛指裸名词出现，**无任何限定**（不指明消息类型、不指明接收者角色）。
  - 例："有**新消息**时通知**用户**"——消息未分类、用户未圈定 → F2 成立。

**反向特征（须全部不出现）**——出现任何一个即不命中：

- **B1 消息范围限定**：消息类型/来源的枚举或举例（"审批结果/评论/@我/系统公告…这类消息"）。
  - 例："**审批通过或驳回时**通知**申请人**" → B1 出现。
- **B2 接收者圈定**：通知到谁的具体指明（角色/关系/订阅者）。
  - 例："通知**提交人及其上级**" → B2 出现。
- **B3 渠道指明**：App 推送 / 短信 / 邮件 / 站内信等渠道说明。
  - 例："通过**短信和 App 推送**通知" → B3 出现。

### 判定

```
(F1 ∧ F2) ∧ ¬B1 ∧ ¬B2 ∧ ¬B3 → 命中 R-S19-P9
```

判定式读法：**左边**（声明了通知意图，且"消息""用户"至少一个名词裸奔无限定）**同时右边**（消息范围、接收者、渠道一个没圈）→ 命中。

### 判定过程示例

**例 1（命中）**：

> "有新消息时通知用户。"

| 特征 | 结果 | 依据 |
|---|---|---|
| F1 | ✓ | "有新消息时通知用户" |
| F2 | ✓ | "消息""用户"均裸名词 |
| B1 | ✗ | 消息类型全无 |
| B2 | ✗ | 通知谁全无 |
| B3 | ✗ | 渠道全无 |

→ **命中**：实证显示 6 组互斥——消息所指（仅聊天会话 vs 仅系统事件 vs 全量混装，三方收敛为 IM/待办/收件箱三种不可互换的产品）、渠道（App 推送离线可达 vs 仅站内红点 vs 邮件+页内提示）、触发时机（逐条实时 vs 日摘要聚合 vs 分钟级批处理）、点击落地（深链会话 vs 业务单据 vs 收件箱列表）、通知对象（接收者本人 vs 角色组全员）、免打扰频控（全套 vs 无）。

**例 2（不命中）**：

> "审批单被驳回时，通过站内信和短信通知提交人。"

B1（审批驳回事件）、B2（提交人）、B3（站内信+短信）全部出现 → **不命中**（时机/已读等仍可能缺，但范围已圈定，属其他规则或人工）。

## 说明

本规则检测通知类需求的**核心名词范围失焦**，与通知的业务领域无关（审批/评论/告警/订单状态通知均适用）。缺口实质：通知需求 = 消息范围（通知什么）× 接收者（通知谁）× 渠道（怎么送达）。"有新消息时通知用户"把两个最重的决策名词留成泛指——"消息"可以是用户间聊天、系统事件或全量，三种理解各自成立且产出不可互换的产品；"用户"可以是当事人一人或角色组全员，误发面完全不同。范围失焦比细节缺失更致命：细节缺失（如时机）实现者还能选合理默认值，范围失焦则连"做什么"都三向分叉，验收时各方对"通知了什么"的预期根本不同。与 P1 的分界：P1 是"该有的决策点没写"（规则层缺口），本规则是"写了但核心名词未圈定范围"（名词层缺口），实证中三条互斥产品形态的直接证据落在 P9。

## 误报注意

1. **名词在上下文已圈定**：需求段落上文已枚举消息类型/角色定义（"消息分 A/B/C 三类…本条指 A 类"）——裸名词实际有指代，不命中，需跨段落核对；
2. **通知为纯技术事件**："支付回调通知商户系统"——通知对象（商户系统）与内容（支付结果）由协议限定，范围无歧义，不命中；
3. **明确的全量语义**："所有消息都通知所有人"是显式决策（虽然可疑），范围已圈定，不命中本规则（可提示复核产品合理性）。

## 漏报注意

1. **部分圈定**："审批消息通知相关人"——B1 出现但"相关人"仍是裸名词（B2 缺），部分定义变体，需逐名词核对圈定度；
2. **圈定藏在代词/省略**："收到回复后通知他"——范围由代词承接，需回溯指代链后再判定；
3. **口语化通知表述**："来新消息了要提醒一下用户""给用户推个通知"——F1 词表需覆盖口语触发结构。
