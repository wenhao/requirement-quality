# R-S05-P1 列表需求未定义字段/查询/分页/操作

- **场景**：S05 列表/表格　**标签**：[P1-不完整](../../知识库/缺陷标签.md)
- **验证**：多解实现验证通过（2026-10-20，N=3，分歧：产品定位（B 端管单 vs C 端看单）/字段选择/查询方式/分页形态/操作列全分歧）

## 命中条件

**正向特征（须出现）**：

- **F1 列表实体声明**："做一个/需要/开发 + 列表页/列表/表格/清单"类结构。
  - 例："**做一个**订单管理**列表页**" → F1 成立。
- **F2 内容指代不完整**：展示内容用"XX 信息/相关数据/订单信息"类**概括性指代**，或仅列部分字段名而无字段全集。
  - 例："展示**订单信息**" → F2 成立（哪些信息？未定义）。
- **F3 功能动词空泛**：支持查询/支持搜索/可以筛选——查询**条件与方式**未定义。
  - 例："**支持查询**" → F3 成立（查什么字段？精确还是模糊？）。

F1 为必要条件，F2、F3 至少满足其一。

**反向特征（须全部不出现）**：

- **B1 字段清单**：明确的字段列举（含字段名的并列清单或字段表）。
  - 例："展示**订单号、金额、状态、下单时间**" → B1 出现。
- **B2 查询条件定义**：查询字段 + 匹配方式（精确/模糊/范围）。
  - 例："按订单号**精确**查询，按时间**范围**筛选" → B2 出现。
- **B3 分页/排序定义**：每页条数 / 排序字段 / 无限滚动 等分页排序要素。
  - 例："默认每页 **20 条**，按**下单时间倒序**" → B3 出现。

### 判定

```
(F1 ∧ (F2 ∨ F3)) ∧ ¬B1 ∧ ¬B2 ∧ ¬B3 → 命中 R-S05-P1
```

判定式读法：**左边**（要做列表，但展示内容或查询方式是指代/空泛的）**同时右边**（字段、查询条件、分页排序全没定义）→ 命中。

### 判定过程示例

**例 1（命中）**：

> "做一个订单管理列表页，展示订单信息，支持查询。"

| 特征 | 结果 | 依据 |
|---|---|---|
| F1 | ✓ | "做一个…列表页" |
| F2 | ✓ | "订单信息"概括指代 |
| F3 | ✓ | "支持查询"空泛 |
| B1/B2/B3 | ✗ | 字段/查询条件/分页排序全无 |

→ **命中**：实证显示开发者将其实现为运营侧 9 列筛选表格、消费者侧状态 Tab 卡片流、API filter DSL 三种完全不同的产品。

**例 2（不命中）**：

> "订单列表展示订单号、金额、状态、下单时间四列，按单号精确查询，每页 20 条按时间倒序。"

B1（四字段列举）、B2（单号精确）、B3（20 条/时间倒序）出现 → **不命中**。

## 说明

本规则检测列表类需求的**要素缺失**，与列表内容领域无关（订单/商品/日志/工单均适用）。缺口实质：列表需求 = 字段全集 + 查询条件集 + 排序分页 + 行操作 + 使用者定位，五要素中"使用者定位"最隐蔽——实证分歧的根源是需求未说是 B 端管理页还是 C 端消费页，直接导致表格 vs 卡片流的产品形态分叉。

## 误报注意

1. **原型图引用**："列表见原型图，字段以设计稿为准"——B1 以外部形式存在，需人工确认设计稿覆盖度；
2. **复用既有列表**："在现有订单列表上加导出按钮"——列表本身已存在，本需求主体是导出，不命中（应扫导出场景规则）；
3. **明确的 MVP 边界**："一期只做全量列表翻页，查询二期"——分期承诺，不命中。

## 漏报注意

1. **部分字段**：列了 3 个字段但实际需要 8 个——B1 打破命中但字段不全，属"部分定义"缺口，需按字段粒度核对（同 R-S01-P1 的部分约束问题）；
2. **有查询无分页**：给了查询条件但没说分页——B2 出现使本规则不命中，但 B3 单独缺失构成另一变体，可命中放宽版规则（F1∧F2∧¬B1∧¬B3）；
3. **口语化实体**："搞个页面把订单都列出来"——"列出来"即列表语义，F1 词表需覆盖口语表述。
