# R-S27-P4 敏感数据范围依赖个人理解未指明

- **场景**：S27 数据安全与防护　**标签**：[P4-隐含假设](../../知识库/缺陷标签.md)
- **验证**：多解实现验证通过（2026-10-20，N=3，6 组冲突性假设：加密层级/覆盖范围/可检索性/展示脱敏/密钥管理/历史回填）

## 命中条件

**正向特征（须出现）**：

- **F1 加密要求声明**："敏感数据/敏感信息 + 要/需要/必须 + 加密"类结构（存储/传输加密均可）。
  - 例："**敏感数据要加密存储**" → F1 成立；"敏感信息**传输必须加密**" → F1 成立。
- **F2 范围词裸奔**："敏感数据"作为未指明范围的泛指词出现——哪些字段算敏感（密码凭证/手机号身份证 PII/全部）**无枚举、无引用标准、无判定规则**。

**反向特征（须全部不出现）**——出现任何一个即不命中：

- **B1 字段范围界定**：敏感字段的枚举、分类或判定规则（"手机号、身份证、银行卡"/"按个保法 PII 口径"）。
  - 例："手机号、身份证号**等 PII 字段**加密存储" → B1 出现。
- **B2 加密方式约束**：可逆/不可逆、字段级/库级、算法标准的说明。
  - 例："口令**不可逆哈希**，其余 PII **字段级可逆加密**" → B2 出现。
- **B3 配套语义定义**：加密后可否检索、展示是否脱敏、密钥管理的约定。
  - 例："加密后**须支持手机号精确匹配登录**，展示打码" → B3 出现。

### 判定

```
(F1 ∧ F2) ∧ ¬B1 ∧ ¬B2 ∧ ¬B3 → 命中 R-S27-P4
```

判定式读法：**左边**（要求加密，但"敏感"指什么没说）**同时右边**（字段范围、方式约束、配套语义一个没出现）→ 命中。

### 判定过程示例

**例 1（命中）**：

> "敏感数据要加密存储。"

| 特征 | 结果 | 依据 |
|---|---|---|
| F1 | ✓ | "敏感数据要加密存储" |
| F2 | ✓ | "敏感数据"未指明范围 |
| B1 | ✗ | 无字段枚举 |
| B2 | ✗ | 无方式约束 |
| B3 | ✗ | 无检索/脱敏/密钥约定 |

→ **命中**：实证显示 6 组互斥——加密层级（应用层字段级可逆加密【A/B 趋同】vs 透明存储层 TDE——拖库时 A/B 的身份证是密文乱码，C 打开即全部明文）、覆盖范围（全 PII 枚举逐字段 vs 仅凭证+业务键 vs 不区分字段整库——同一份库文件，身份证在 A 是密文、B 可能未覆盖、C 是明文）、可检索性（密文索引仅精确匹配【A/B 趋同】vs 明文全功能——"按姓名模糊搜"在 C 有、A/B 上线即消失）、展示脱敏（默认打码+明文需审批 vs 原文展示【B/C 趋同】——客服看到 138****要走审批流还是直接看到完整号码）、密钥管理（应用层密钥体系可轮换【A/B 趋同】vs 零密钥——密评问"密钥如何轮换"C 无法应答）、历史回填（停机全量+明文销毁 vs 渐进回填 vs 无需回填——B 上线后一段时间老数据仍明文，保护状态不一致）。

**例 2（不命中）**：

> "手机号、身份证号等 PII 字段加密存储：口令类不可逆哈希；加密后支持手机号精确匹配；界面展示默认打码，查看明文需审批。"

B1、B2、B3 全部出现 → **不命中**。

## 说明

本规则检测加密类需求的**范围隐含假设**，与数据领域无关（用户数据/财务数据/医疗数据加密均适用）。缺口实质："敏感数据"是判定负载词——它不描述字段而**预设了判定已完成**，但判定标准（哪些字段敏感）因人而异：金融合规背景者按 PII 枚举全覆盖，SaaS 工程师按业务键取舍，极简派整库一锅端。P4 的典型结构在此完全显形：写作者脑中有明确的敏感清单，误以为读者共享同一清单；三个读者各持一份不同清单，产出三个安全水位完全不同的系统。且加密方式的分歧会反向破坏业务功能（模糊搜索消失、登录检索失效）——安全与可用性的权衡点未指明，实现者只能替业务做主。**自我指涉 + 反向破坏**双重风险，使该场景成为 P4 的标本案例。

## 误报注意

1. **标准引用兜底**："敏感字段按 GB/T 35273 个人信息安全规范界定"——B1 以标准引用形式存在，不命中，需人工确认标准覆盖业务特有字段；
2. **密评/等保上下文**：项目已过密评、加密方案已成文——B1–B3 由既有方案承载，不命中；
3. **单纯传输加密**："全站 HTTPS"——传输加密无字段歧义（全部流量），F2 的范围问题不存在，不适用本规则。

## 漏报注意

1. **范围半枚举**："手机号要加密"——B1 弱出现（单字段），但身份证/地址等其余字段是否属敏感仍开放，按字段清单逐项核对；
2. **加密词歧义**："加密"可能指哈希（不可逆）也可能指加密（可逆）——密码"加密存储"若实指哈希，B2 语义需按上下文判定；
3. **脱敏与加密混用**："敏感信息要脱敏"——脱敏（展示层）与加密（存储层）是不同控制点，F1 需识别指哪种控制，两者都缺范围定义时各自命中对应规则。
