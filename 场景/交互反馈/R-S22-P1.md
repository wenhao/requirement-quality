# R-S22-P1 空态未定义内容要素与空语义区分

- **场景**：S22 空态/首次使用　**标签**：[P1-不完整](../../知识库/缺陷标签.md)
- **验证**：多解实现验证通过（2026-10-20，N=3，5 组冲突性假设：行动入口/筛选空与真空区分/首次引导/异常态归属/按钮指向）

## 命中条件

**正向特征（须出现）**：

- **F1 空态要求声明**："为空/无数据/没有数据 + 时 + 展示/显示/出现 + 空状态/空页面/空态"类结构。
  - 例："**列表为空时展示空状态页面**" → F1 成立。
- **F2 内容要素缺席**：空态页展示什么（文案之外的要素——引导按钮/新建入口/插画说明）**未定义**。

**反向特征（须全部不出现）**——出现任何一个即不命中：

- **B1 空态内容定义**：文案 + 行动按钮/引导动作的说明（"展示'暂无项目'文案和新建按钮"）。
  - 例："空态展示**'暂无数据'和'新建'按钮**" → B1 出现。
- **B2 空语义区分**："筛选后无结果"与"真空数据"是否区分及各自展示的说明。
  - 例："**筛选无结果时提示调整条件**，与真空数据区分展示" → B2 出现。
- **B3 异常态归属**：无权限/加载失败是否算空态、如何展示的说明。
  - 例："**无权限单独展示申请页**，不算空态" → B3 出现。

### 判定

```
(F1 ∧ F2) ∧ ¬B1 ∧ ¬B2 ∧ ¬B3 → 命中 R-S22-P1
```

判定式读法：**左边**（要求有空态页，但页面内容没说）**同时右边**（内容要素、空语义区分、异常态归属一个没提）→ 命中。

### 判定过程示例

**例 1（命中）**：

> "列表为空时展示空状态页面。"

| 特征 | 结果 | 依据 |
|---|---|---|
| F1 | ✓ | "列表为空时展示空状态页面" |
| F2 | ✓ | 页面里放什么全无 |
| B1 | ✗ | 文案/按钮要素无 |
| B2 | ✗ | 筛选空与真空无区分 |
| B3 | ✗ | 权限/失败归属无 |

→ **命中**：实证显示 5 组互斥——行动入口（插画+CTA 主按钮 vs 按态情境操作 vs 纯文案无事可做）、筛选空与真空区分（严格区分+清除筛选引导 vs 统一空态——搜索无结果时 B 用户一键找回列表，A 用户被误导去新建）、首次引导兼任（空态即 onboarding 位 vs 只陈述事实）、异常态归属（独立无权限页/错误页 vs 混入空态——无权限用户在混入方案下误以为"自己没数据"）、按钮指向（新建/导入 vs 按态分配 vs 不设）。

**例 2（不命中）**：

> "列表为空时展示空态页：文案'暂无订单'+ 新建订单按钮；筛选后无结果时提示'无匹配'并提供清除筛选链接；无权限单独展示申请权限页。"

B1、B2、B3 全部出现 → **不命中**。

## 说明

本规则检测空态类需求的**职责与内容缺失**，与列表内容无关（订单/项目/消息列表空态均适用）。缺口实质：空态需求 = 内容要素 × 空的语义口径 × 异常态归属。"空状态页面"看似一个简单 UI 件，实则是三个决策的复合：① 页面承载什么职责（纯陈述事实 vs 转化位引导新建 vs 首次使用教育位）；② "为空"有至少三种语义（真空数据/筛选无结果/加载失败或无权限），误判语义直接误导用户（把筛选问题当成没数据去新建）；③ 异常与空混用时用户得到错误的归因。B 端与 C 端对空态的默认心智本就分化（转化 vs 区分态），无业务常识可收敛，三向分叉全部用户可感知。

## 误报注意

1. **设计系统空态组件**："空态用组件库 Empty 组件"——B1 以组件默认形式存在，但组件的情境配置（带不带按钮）仍开放，需人工确认；
2. **全局空态规范**："空态规范见设计规范文档"——B1–B3 以规范形式存在，需人工确认规范覆盖筛选/权限分支；
3. **明确纯展示意图**："空态只放一句'暂无数据'，别的都不加"——内容要素为显式决策（极简），不命中（B1 以否定形式出现）。

## 漏报注意

1. **部分要素**："空态要有新建引导"出现 B1（按钮）但筛选/权限区分未说——部分定义变体，逐要素核对；
2. **空态口语化**："没数据的时候给个提示页""列表空了别白屏"——F1 词表需覆盖口语表述；
3. **空态范围泛化**："所有列表都要有空态"——单条规则覆盖多页面时各页面的行动按钮指向（新建/导入/联系管理员）仍各自开放，需按页面粒度核对 B1。
