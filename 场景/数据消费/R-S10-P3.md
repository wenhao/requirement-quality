# R-S10-P3 排序分页需求用主观词无量化

- **场景**：S10 排序/分页　**标签**：[P3-主观模糊](../../知识库/无效需求标签.md)
- **验证**：多解实现验证通过（2026-10-20，N=3，5 组冲突性假设：排序键/分页交互/刷新机制/翻页一致性/总量信息）

## 命中条件

**正向特征（须出现）**：

- **F1 排序主诉词**："最新 / 最近的 / 按时间 / 默认排序"类默认序表述，**未指明排序键字段**（创建时间 / 更新时间 / 业务时间）。
  - 例："默认展示**最新**数据" → F1 成立（最新的"新"以哪个时间字段为准？未说）。
- **F2 分页触发的模糊量化**："数据多了 / 量大时 / 太多时 + 要分页 / 需要分页"类结构，"多了"**无数值阈值**。
  - 例："列表**数据多了**要分页" → F2 成立（多少算多？未说）。
- **F3 分页要素缺失**：每页条数 / 翻页方式（页码 / 无限滚动）/ 总量展示，任一都未出现。

F1、F2 至少满足其一，F3 须同时成立（分页需求却无任何分页参数）。

**反向特征（须全部不出现）**：

- **B1 排序键定义**：具体排序字段 + 方向（按下单时间倒序 / 按创建时间升序）。
  - 例："按**下单时间倒序**" → B1 出现。
- **B2 分页参数**：每页条数（具体数字）/ 页码跳转 / 无限滚动 等分页方式说明。
  - 例："**每页 20 条**，页码跳转" → B2 出现。
- **B3 交互定义**：下拉刷新 / 触底加载 / 新数据提示 等刷新或加载行为说明。
  - 例："**触底自动加载**，**下拉刷新**" → B3 出现。

### 判定

```
((F1 ∨ F2) ∧ F3) ∧ ¬B1 ∧ ¬B2 ∧ ¬B3 → 命中 R-S10-P3
```

判定式读法：**左边**（排序或分页的主诉是"最新/多了"类主观词，且分页要素全缺）**同时右边**（排序键、分页参数、加载交互全没定义）→ 命中。

### 判定过程示例

**例 1（命中）**：

> "订单列表默认展示最新数据，列表数据多了要分页。"

| 特征 | 结果 | 依据 |
|---|---|---|
| F1 | ✓ | "最新"无排序键 |
| F2 | ✓ | "数据多了"无阈值 |
| F3 | ✓ | 条数/方式/总量全无 |
| B1/B2/B3 | ✗ | 排序键/分页参数/交互全无 |

→ **命中**：实证显示"最新"被实现为按下单时间、支付时间、创建时间三种排序键——列表首条订单三案各不相同；分页被实现为页码分页、无限滚动、接口双支持三种形态。

**例 2（不命中）**：

> "订单列表按下单时间倒序，每页 20 条页码翻页，支持下拉刷新。"

B1（下单时间倒序）、B2（20 条/页码）、B3（下拉刷新）出现 → **不命中**。

## 说明

本规则检测排序分页需求的**量化缺失**，与列表领域无关（订单/消息/日志/动态均适用）。缺口实质：排序分页需求 = 排序键（哪个时间字段、什么方向）× 分页参数（每页条数、翻页方式）× 刷新机制（进入刷新/下拉/新数据提示）。"最新"和"多了"是两枚主观地雷："最新"看似无歧义实则排序键三解互斥，直接决定列表首条内容；"多了"把分页阈值决策外包给开发。P1（要素未列）常伴随，但主诉词的主观性是根因——量化的排序分页定义（B1–B3）缺位时，主观词必然产出互斥实现。

## 误报注意

1. **平台默认引用**："分页沿用列表组件默认"——分页参数以外部形式存在，需人工确认组件默认值可接受；
2. **分期承诺**："一期全量展示，分页等数据量上来再做"——显式不分页的决策，不命中；
3. **主体不是分页**："列表加个筛选，顺便调下默认排序"——分页排序是附带提及，应扫主体功能。

## 漏报注意

1. **有排序键无分页**：给了"按时间倒序"但没说条数——B1 出现打破命中，B2 单独缺失仍是缺口（排序定义了、分页没定义）；
2. **伪量化**："展示最近的数据""适量分页""合理条数"——"最近/适量/合理"不构成 B1/B2 的量化，应仍命中；
3. **翻页一致性缺口**：B1–B3 齐备但"翻页时有新数据插入怎么办"未说——属深水区缺口，本规则不覆盖，需语义级判定。
