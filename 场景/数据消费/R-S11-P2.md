# R-S11-P2 报表指标口径未定义致不可验收

- **场景**：S11 报表/统计　**标签**：[P2-不可验证](../../知识库/无效需求标签.md)
- **验证**：多解实现验证通过（2026-10-20，N=3，5 组冲突性假设：指标口径/时间口径/趋势形态/范围新鲜度/退款处理）

## 命中条件

**正向特征（须出现）**：

- **F1 报表实体声明**："做一个/需要 + 报表 / 统计 / 看板 / 数据分析页"类结构。
  - 例："**做一个**销售统计**报表**" → F1 成立。
- **F2 指标名称出现但口径未定义**：出现业务指标名（销售额 / 订单量 / 用户数 / 转化率），但**无计算口径**（含不含退款、按什么时间归属、分子分母是什么）。
  - 例："能看到每天的**销售额**" → F2 成立（下单额？实付额？扣不扣退款？未说）。
- **F3 效果概括语**："整体趋势 / 大盘 / 走势 / 概览 / 一目了然"类效果语，无具体形态定义。
  - 例："和**整体趋势**" → F3 成立（折线？环比？移动平均？未说）。

F1 为必要条件，F2、F3 至少满足其一。

**反向特征（须全部不出现）**：

- **B1 指标口径定义**：计算规则的显式说明（含/不含、扣减项、分子分母、去重规则）。
  - 例："销售额 = **支付成功金额扣除退款**" → B1 出现。
- **B2 时间口径定义**：归属时间字段（按支付时间 / 下单时间）+ 统计周期（自然日 / T+1 结算日）。
  - 例："按**支付时间**归属**自然日**" → B2 出现。
- **B3 数据范围与形态定义**：统计范围（全量 / 近 N 天 / 指定维度）+ 呈现形式（每日折线 / 环比同比 / 明细下钻）。
  - 例："近 **30 天**，每日折线 + **环比**" → B3 出现。

### 判定

```
(F1 ∧ (F2 ∨ F3)) ∧ ¬B1 ∧ ¬B2 ∧ ¬B3 → 命中 R-S11-P2
```

判定式读法：**左边**（要做报表，指标或效果是名称级表述）**同时右边**（指标口径、时间口径、范围与形态全没定义）→ 命中。

### 判定过程示例

**例 1（命中）**：

> "做一个销售统计报表，能看到每天的销售额和整体趋势。"

| 特征 | 结果 | 依据 |
|---|---|---|
| F1 | ✓ | "做一个…报表" |
| F2 | ✓ | "销售额"无口径 |
| F3 | ✓ | "整体趋势"无形态 |
| B1/B2/B3 | ✗ | 口径/时间/范围全无 |

→ **命中**：实证显示"销售额"被实现为实付净额（扣退款）、接口字段直接求和、下单金额（含未支付）三种口径——同一天三个报表出三个数且都自认正确；"趋势"被实现为移动平均+环比、折线+回归线、只给日序列三种形态。验收方无法判定任一实现错误。

**例 2（不命中）**：

> "销售日报：销售额 = 支付成功金额扣除当日退款，按支付时间归属自然日，近 30 天每日折线并展示环比。"

B1（支付金额扣退款）、B2（支付时间/自然日）、B3（30 天/折线/环比）出现 → **不命中**。

## 说明

本规则检测报表需求的**验收标准缺失**，与指标领域无关（销售/运营/财务/行为报表均适用）。缺口实质：报表需求的可验收性完全由口径承载——指标口径 × 时间口径 × 范围形态三者共同定义"报表做完"的标准。三口径任一缺失，不同实现都能逻辑自洽，验收退化为"看起来像报表就行"。报表是 P2 的重灾区：功能类需求"做错了能看出来"，报表"做错了也像对的"——数字本身就是产物，口径错则数字全错而界面无感。P1（口径未列）常伴随，但根本是 P2：缺口不在信息量而在**不可证伪性**。

## 误报注意

1. **指标字典引用**："指标口径见数据字典 / 口径文档"——B1 以外部形式存在，需人工确认文档覆盖该报表全部指标；
2. **既有报表扩展**："在现有销售日报上加个渠道维度"——口径继承自既有报表，本需求主体是新维度，不命中；
3. **探索性分析任务**："拉个数据看看销售情况"——这是分析任务不是报表需求，无验收概念，不命中。

## 漏报注意

1. **部分口径**：定义了销售额口径但没说时间归属——B1 出现打破命中，B2 缺失仍是缺口，需按口径粒度核对（每个指标 × 每个维度）；
2. **伪口径**："真实销售额""实际业绩"——"真实/实际"不构成计算规则，应仍命中；
3. **默认口径假设**：B1–B3 齐备但"退款发生在次日怎么入账"类深水口径未说——属口径完备性的深水区，需语义级判定。
