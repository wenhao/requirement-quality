# R-S08-P1 搜索功能未定义检索范围与方式

- **场景**：S08 搜索/筛选　**标签**：[P1-不完整](../../知识库/缺陷标签.md)
- **验证**：多解实现验证通过（2026-10-20，N=3，6 组冲突性假设：数据范围/匹配语义/触发交互/结果组织/无结果策略/输入辅助）

## 命中条件

**正向特征（须出现）**：

- **F1 搜索功能声明**："加一个/做一个/需要/支持 + 搜索/检索/查找/找 + 功能/能力"类结构。
  - 例："**加一个搜索功能**" → F1 成立；"支持**查找**商品" → F1 成立。
- **F2 目的或效果表述**："方便/帮助/让用户 + 快速/更快 + 找到/定位"类目的语，或直接以"找到想要的 xx"收尾。
  - 例："方便用户**快速找到**想要的商品" → F2 成立。
- **F3 检索对象为概括指代**：搜索对象仅到实体级（商品/订单/用户/内容），未落到字段级。
  - 例："搜索**商品**" → F3 成立（搜标题？描述？SKU？未说）。

F1 为必要条件，F2、F3 至少满足其一。

**反向特征（须全部不出现）**：

- **B1 检索范围定义**：可搜索字段列举（标题/名称/SKU/编号/描述），或"全字段/仅标题"类范围说明。
  - 例："按**商品名称和 SKU** 搜索" → B1 出现。
- **B2 匹配方式定义**：精确 / 模糊 / 前缀 / 分词 / 包含，任一匹配语义说明。
  - 例："名称**模糊**匹配，编号**精确**匹配" → B2 出现。
- **B3 触发与结果行为定义**：实时/输入即搜 / 回车提交 / 点击按钮；无结果时的处理（空态提示 / 降级推荐）。
  - 例："**回车触发**搜索，**无结果时提示并展示热销推荐**" → B3 出现。

### 判定

```
(F1 ∧ (F2 ∨ F3)) ∧ ¬B1 ∧ ¬B2 ∧ ¬B3 → 命中 R-S08-P1
```

判定式读法：**左边**（要做搜索，且以目的语或概括对象表述）**同时右边**（检索范围、匹配方式、触发与结果行为全没定义）→ 命中。

### 判定过程示例

**例 1（命中）**：

> "在商品列表页加一个搜索功能，方便用户快速找到想要的商品。"

| 特征 | 结果 | 依据 |
|---|---|---|
| F1 | ✓ | "加一个搜索功能" |
| F2 | ✓ | "方便用户快速找到" |
| F3 | ✓ | "商品"实体级指代，未到字段 |
| B1/B2/B3 | ✗ | 范围/匹配/触发结果全无 |

→ **命中**：实证显示三人分别实现为服务端全库 LIKE 子串匹配 + 独立搜索页、前端已加载页本地过滤 + 回车触发、ES 分词检索 + 输入即搜 + 纠错回退——搜"不在当前页的商品"一返无一能召回，错别字一纠错一出空。

**例 2（不命中）**：

> "商品列表支持按名称模糊、SKU 精确搜索，回车触发，无结果时展示类目导航。"

B1（名称/SKU）、B2（模糊/精确）、B3（回车触发 + 无结果处理）出现 → **不命中**。

## 说明

本规则检测搜索类需求的**检索要素缺失**，与搜索对象领域无关（商品/订单/文档/成员均适用）。缺口实质：搜索需求 = 检索范围（搜哪些字段、哪个数据集）× 匹配语义（模糊/精确/分词）× 触发交互（实时/提交）× 结果组织（重排/就地过滤）× 无结果策略，五要素全缺时开发只能按自己背景选择检索模型，产出在"能不能搜到"这一根本行为上互斥。P6（"快速找到"不精确动词）常伴随出现，但根因是 P1。

## 误报注意

1. **平台既有搜索组件**："搜索沿用现有全局搜索组件"——检索能力以外部形式存在，需人工确认组件覆盖范围；
2. **明确的筛选器需求**："列表加名称/SKU 筛选框"——这是筛选（B1/B2 齐备）不是搜索，不命中；
3. **目的语闲笔**：搜索只是背景陈述，需求主体是别的功能时不命中，应扫主体。

## 漏报注意

1. **有范围无方式**：给了搜索字段但没说模糊还是精确——B1 出现打破命中，B2 单独缺失构成变体（F1∧F3∧¬B2∧¬B3）；
2. **伪定义**："支持智能搜索""像淘宝那样搜"——"智能/像 xx 那样"不构成 B1/B2 的实质定义，应仍命中；
3. **搜索口语化**："搞个查找的功能""能搜一下"——F1 词表需覆盖口语检索表述。
