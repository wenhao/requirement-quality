# 调研方法论

> 本文档记录"需求有效性"调研的整体思路与核心决策（2026-10-19 grill-me 审查会话定稿），是仓库一切产出的方法论依据。

## 背景

研究目标：什么样的需求描述拿去开发，会产出一个"能用但不符合预期"的结果。

冷启动难题：手头没有真实需求样本，无法从真实缺陷出发归纳。因此采用**先合成穷举、后真实校准**的路线。

## 核心思路

**穷举需求分析的场景，再通过 AI 在每个场景下穷举无效需求的写法。** 因为没有实际的需求，只能先穷举场景再去验证。

整个调研围绕一个中心产出物展开，由三层机制支撑。

## 五项核心决策

### 1. 终极产出物：场景 × 缺陷矩阵清单

- 矩阵以场景为行、缺陷类型为列；
- 空格 = 未覆盖的盲区，直观暴露穷举遗漏；
- 可降级为 AI 辅助需求澄清（clarifier）的规则 / prompt 素材。

### 2. 矩阵主轴：场景

场景做主轴（而非缺陷类型），保留原始思路。配套代价是必须解决场景穷尽性问题：

- **穷举依据**：外部分类学交叉对照——用 ISO/IEC/IEEE 29148 需求分类、主流 PRD 模板章节结构、需求缺陷（requirement smells）学术分类等外部权威来源交叉拼出场景骨架；
- **穷尽判据**：多来源交叉后无新增场景，即视为穷尽；
- 避免凭直觉往下列场景——列漏一个场景，矩阵就有一整行盲区。

### 3. AI 生成样本的质检：多解实现验证法

AI 生成"无效需求写法"很容易，但可能出现伪缺陷（信息其实够了，是 AI 过度挑刺）或同质化（变着措辞重复同一缺口）。判定机制：

- 把候选需求描述交给 **N 个相互独立的 AI 开发者**各自实现；
- **产出分歧显著 = 信息缺口实证存在**（必填规则不同、边界处理不同等）；
- 产出趋同 = 伪缺陷，剔除；
- 分歧点直接写入样本的"缺陷分析"段，作为缺陷的实证证据；
- 全流程可自动化，辅以少量人工抽检校准。

### 4. 合成与真实样本：双层闭环互哺

- **合成层**：AI 穷举 + 多解验证，先铺满矩阵骨架（解决冷启动）；
- **真实层**：从开源项目 issue / 公开 SRS/PRD 文档 / 外包平台公开需求描述主动采集；
- **回测机制**：真实样本进来后检验能否被矩阵已有模式解释——能 → 覆盖度 +1；不能 → 盲区，新增行列；
- 两条线从并列变为互哺：合成层提供结构，真实层校准分布。

### 5. 物理承载：目录 + 标签 + MATRIX.md

- `cases/` 场景目录结构保持不变，场景目录 = 矩阵的行；
- 缺陷类型作为样本文件内的**结构化标签**（可多标签），= 矩阵的列，解决一个样本命中多个缺陷类型的问题；
- 顶层 `MATRIX.md` 汇总行 × 列覆盖视图，从样本标签自动汇总，空格即盲区；
- 覆盖标准：每个矩阵格子至少 1 个通过多解验证的样本才算"已覆盖"。

## 执行顺序

```
外部分类学拼场景骨架
        │
        ▼
AI 逐场景生成无效写法候选 ──► 多解实现验证 ──► 筛选入库
        │                                         │
        └────────── 可并行流水线化 ────────────────┘
                                                  │
                                                  ▼
                                    打标签、更新 MATRIX.md
                                                  │
                                                  ▼
                                    真实样本回测矩阵覆盖度
```

其中"生成 → 验证 → 入库"三步可流水线化批量推进。

## 与 README 定位的关系

README 定位"收集真实写法样本"没有被抛弃：合成样本铺结构，真实样本校准分布。真实样本仍是仓库的最终权威来源，合成样本是冷启动期的骨架与验证探针。
