# 缺陷标签体系 v1

> 本文档定义"场景 × 缺陷矩阵"的**列**：缺陷类型标签。样本可打多个标签。构建方法与场景骨架一致——外部分类学交叉对照（见 [METHODOLOGY.md](METHODOLOGY.md) 决策 2），两族来源映射后无新增标签即收敛。

## 构建方法

| 来源族 | 具体来源 | 贡献 |
|---|---|---|
| **P. 实践起点** | README 已有六类缺陷（缺校验/缺边界/缺验收/隐含假设/主观形容词/流程断点） | 来自真实观察，贴近产品日常 |
| **Q. 学术分类** | Montgomery 等 requirement smells 系统综述（15 smell）；Rimay 九 smell 目录；ISO 29148 良构需求特性（unambiguous/complete/verifiable/singular…） | 学术验证 + 补充语言类缺陷 |

**交叉验证结果**：Q 映射到 P 后全部可归类（如 open-ended/loopholes → 归入 P1 缺信息量），但 Q 反向补充了 P 缺失的**语言层面缺陷**（P7–P8）与**结构层面缺陷**（P9）——这正是交叉对照的价值。收敛后共 9 个标签。

## 标签体系（9 类）

### 信息量缺陷（写了但不够）

| 标签 | 定义 | 典型写法 | 来源 |
|---|---|---|---|
| `P1-不完整` | 关键决策点缺失，开发必须自行假设 | 表单没说必填性；流程没说谁审批 | P（缺校验/缺边界合并归此） |
| `P2-不可验证` | 无验收标准，"做到什么程度算完"缺失 | 只有功能描述没有完成定义 | P + Q：non-verifiable |
| `P3-主观模糊` | 含主观形容词/副词，无量化指标 | "界面要美观"、"性能要流畅" | P + Q：subjective language |
| `P4-隐含假设` | 依赖未言明的上下文，"和现有系统一致" | 未指明参照版本、参照行为 | P + Q：incomplete references |

### 语言缺陷（写了但会读歪）

| 标签 | 定义 | 典型写法 | 来源 |
|---|---|---|---|
| `P5-歧义表述` | 一句话多种解读，开发各取所需 | "或"连接的条件；模糊代词 | Q：coordination ambiguity、vague pronouns |
| `P6-不精确动词` | 动作动词无精确定义 | "处理"、"支持"、"优化" | Q：not precise verb |

### 结构缺陷（该有的段落没有）

| 标签 | 定义 | 典型写法 | 来源 |
|---|---|---|---|
| `P7-流程断点` | 只写正常路径，失败/回退/撤销缺失 | 有提交无失败处理 | P（保留） |
| `P8-非原子` | 一条需求塞多个动作，无法分别验收 | "添加并允许订阅" | Q：non-atomic requirement |
| `P9-范围失焦` | 边界不清，做什么/不做什么未定义；或混入背景叙述 | "增加消息提醒功能"（提醒什么？给谁？） | Q：not requirement、open-ended + PRD 实践"需求范围"章节缺失 |

## 与 README 旧六类的映射

| README 旧标签 | 归属 |
|---|---|
| 缺少校验规则 | → `P1-不完整` |
| 缺少边界条件 | → `P1-不完整`（边界是完整性的一种） |
| 缺少验收标准 | → `P2-不可验证` |
| 隐含假设 | → `P4-隐含假设` |
| 主观形容词 | → `P3-主观模糊` |
| 流程断点 | → `P7-流程断点`（独立保留，出现频率高） |

## 使用规则

1. 样本头部以 `缺陷标签：P1-不完整, P2-不可验证` 格式列出，可多标签；
2. 标签只描述**信息缺口类型**，不描述严重程度；
3. 新增标签需先修订本文件再使用，避免矩阵列漂移。
