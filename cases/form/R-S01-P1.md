# R-S01-P1 表单字段规则缺失

- **场景**：S01 表单（新增/编辑）　**标签**：[P1-不完整](../../docs/DEFECTS.md)
- **验证**：多解实现验证通过（2026-10-20，N=3，5 处用户可感知分歧：布局/姓名长度/地址下限/号码前缀处理/字符集限制）

## 命中条件

**正向特征（须出现）**：
- **F1 实体声明**：出现"做一个 / 开发一个 / 需要 / 想要 + 页面 / 功能 / 模块 / 表单"类实体引入结构；
- **F2 内容枚举或动作对**（与 F1 至少满足其一，两者同时出现最典型）：
  - F2a 字段枚举："包括 / 包含 / 含有 + 名词并列清单"（顿号、逗号、和/与连接）；
  - F2b 动作对："可以 / 支持 + 动词 + 和 + 动词"（如"添加和编辑"、"查询和导出"）。

**反向特征（须全部不出现）**：
- **B1 约束词**：必填 / 选填 / 可选 / 格式 / 长度 / 上限 / 下限 / 校验 / 正则 / 限制 / 非空；
- **B2 平台词**：Web / H5 / 小程序 / App / 后台 / PC / 移动端 / 端上；
- **B3 失败路径词**：失败 / 异常 / 重试 / 重复提交 / 网络错误。

### 判定

```
(F1 ∧ (F2a ∨ F2b)) ∧ ¬B1 ∧ ¬B2 ∧ ¬B3 → 命中 R-S01-P1
```

## 说明

本规则检测的是**信息缺口结构**，与枚举的具体字段无关：任何领域的表单需求，只要"列了东西 + 没有任何规则性约束"即命中。缺口的实质是开发必须自行假设字段级规则（必填性/格式/长度/字符集）与关键决策点（平台/数量上限/失败处理），不同假设产出用户可感知的不同系统。

## 误报注意

1. **外部引用**：需求含"规则详见附件 / 校验规则见 XX 文档"时不命中——信息可能在外部文档中，需人工确认文档是否真实覆盖；
2. **明确的分期承诺**："一期先做界面，校验规则二期补充"属于分期决策而非缺口，不命中；
3. **纯展示型表单**：若上下文表明表单不落库（如筛选表单），字段规则缺失的影响面不同，降级为提示而非缺陷。

## 漏报注意

1. **部分约束**：出现个别约束词但只覆盖部分字段时，B1 被稀释导致漏报——扫描时应按字段粒度核对：枚举的每个字段是否都有规则归属（显式约束或显式豁免）；
2. **约束词歧义**："支持"既可作动作对连接词（F2b）也可能是约束表述（"支持 20 条以内"），需按语义而非词面分类；
3. **隐式枚举**：字段不并列而是散落在句中时 F2a 不触发，需先做实体抽取再套规则。

## 追问方向

命中后 clarifier 应要求补充（内容无关清单）：

1. 目标平台与形态：Web 后台 / H5 / 小程序，承载形式（弹窗 / 抽屉 / 独立页）；
2. 字段级校验表：每字段的必填性、格式规则、长度上下限、字符集限制；
3. 校验时机与提示方式：失焦校验 or 提交时统一校验，错误提示位置；
4. 记录数量上限及达到上限后的交互；
5. 重复提交、保存失败时的交互与数据一致性要求；
6. 验收标准：合法 / 非法输入的示例清单。
