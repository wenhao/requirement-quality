# requirement-quality

研究**需求的有效性**：什么样的描述会让开发自行假设，并产出“能用但不符合预期”的系统。

本仓库沉淀了一套内容无关的需求质量治理体系：**9 类无效需求标签 × 43 个场景 × 45 条可执行扫描规则**。规则可交给 AI 扫描任意中文需求文本；命中即指出信息缺口，不追问、不评分。

## AI 消费入口

默认不要把全库注入模型，按以下顺序渐进读取：

| 层级 | 文件 | 用途 |
|---|---|---|
| L0 | [`_agent-manifest.yaml`](_agent-manifest.yaml) | 空间、披露协议、域清单与状态 |
| L1 | [`_index.md`](_index.md) | 空间地图与候选域定位 |
| L2 | `*/_domain-context.md` | 域内规则摘要、触发信号与阅读边界 |
| L3 | `*/规则-*.md` | 精确 F/B 特征、判定式、示例与误报边界 |
| L4 | [`99-证据/_index.md`](99-证据/_index.md) | 多解验证、真实回测与争议证据 |
| L5 | [`95-学习旅程/_index.md`](95-学习旅程/_index.md) | 明确进入学习场景后才读取 |

常规扫描默认读取 L0–L3；单次任务自动打开的正文页面不超过 8 个。L4 仅用于审计与争议，L5 不参与扫描。

```text
  ×

```

## 规则格式

每条规则自包含，frontmatter 提供 AI 索引字段，正文固定包含：

1. 规则定位与验证摘要；
2. 正向特征 F、反向特征 B；
3. 布尔判定式；
4. 命中与不命中示例；
5. 缺口说明；
6. 误报与漏报边界。

触发词只负责召回，不能替代判定式。反向特征是灭火器：出现任何一个，无论正向特征多完整都不命中。

## 贡献与校验

1. 新场景只允许追加尾部 ID，不改已有 Sxx。
2. 新规则必须通过多解实现验证，同格已有规则时只增强原文件。
3. 规则变更必须同步域索引、L2 摘要、路由表、覆盖矩阵、证据与 manifest。
4. 运行 `python3 scripts/validate_structure.py` 校验目录、链接、frontmatter、规则数量与清单同步。
